HARD RULES
1. Touch nothing outside this directory. No network, no `git push`, no `ssh`/`scp`/`rsync`, no `curl`/`wget`, no package installs. Never call `cargo` directly: Rust lanes use `./cargo-pruef` (queued `cargo build` + `cargo test --no-fail-fast`, prints every failing test) and `./emission-pruef` (queued `instrumente/pruefe-emission.sh`). Text guardians run directly: `python3 instrumente/pruefe-<name>.py`. Scratch files go to `$TMPDIR` (private to you), never `/tmp`.
2. Check Lean ONLY through `./lean-bau` (builds `grammatik/`) and `./lean-probe <file.lean>` (checks one file). `./lean-probe` prints the error count of the COMPLETE output on its first line -- trust that line, not the visible tail. Never call `lake` or `lean` directly.
3. No `sorry`, `admit`, `axiom`, `native_decide`, `unsafe`. No premise whose type is `Prop` itself. Every premise of every theorem you add must be used by its proof.
4. Do NOT: (a) state a conclusion that is one of the premises under another name, or an existential of it; (b) quantify a contract's parameters or result away (`forall rho`, `forall v`) -- contracts hold at their place (entry / return) with the actual values; (c) call something a semantics if it cannot change memory -- worlds come from `execStmt`/`exec`; (d) discard a premise with `intro _` or `have _ :=`. If your result is weaker than the task asks, say so plainly.
5. Unless your task explicitly says to change an existing file, put new Lean work in the NEW file named in your task and add `import Grammatik.<Name>` at the end of `grammatik/Grammatik.lean`. Do not delete or weaken existing theorems. `./lean-bau` must stay green for the whole project.
6. End every Lean file with a comment block `CUTS:` listing exactly what is not proved, plus `#print axioms` for each main theorem.
7. English only in code, comments, docs, commit messages.
8. Commit on your branch: write the message to `arbeitsprotokoll/.commitmsg` (`mkdir -p arbeitsprotokoll` first) and run `./commit.sh`. End the message with the line `Co-Authored-By: muse-agent-1391 <muse-agent-1391@noreply.invalid>`. Never commit a red build: if you cannot get `./lean-bau` green, revert your Lean changes (`git checkout -- grammatik`) and commit only your report.
9. Before you stop, write `MUSE-REPORT-1391.md` in the repository root and commit it: what you did, exact names of new definitions/theorems, the last `./lean-bau` result line, what remains open, and anything in the task you believe is wrong.
10. WORK IN SMALL PIECES. First write a skeleton of at most 60 lines (imports, namespace, one definition), check it with `./lean-probe`, commit when green. Then add ONE definition or lemma at a time with the edit tool and check after each. Very long single writes get cut off and arrive empty.
11. DO NOT END YOUR TURN while work is pending. After every tool result, go on with the next step until the report is committed. If you are stuck, commit the green partial and write the report explaining exactly what blocks you.
12. When the task gives a TARGET STATEMENT, it is fixed: you may adjust only elaboration details (argument order, implicit binders, casts, names of existing helpers). You may NOT add premises or weaken the conclusion. If you believe an extra premise is unavoidable, prove the target with that premise in a separately named theorem AND explain in the report why it is needed and whether it is weaker than the conclusion.

13. INHABITATION (checked mechanically by the merge gate). Every theorem you add whose premise is a universal quantification over program syntax (`Vertrag`, `Stmt`, `Endblock`, `ErgExpr`, `Expr`, `Args`), and every TARGET theorem named in a `ZEUGE:` line of your task, needs a companion theorem named `<name>_zeuge` that instantiates ALL its premises JOINTLY with concrete values and proves them -- on a NON-DEGENERATE program: at least one table that some function writes, and (for run statements) a reached run with at least one step that changes memory. A witness over a declaration with no tables or an empty run does not count. If you cannot build the witness, that is a finding: the premises may be contradictory -- report it, do not weaken the witness.

Rust lanes: patterns of the text guardians move BEFORE the document they read (`CLAUDE.md`, "patterns bilingual before the document moves"). `./cargo-pruef` must end with zero failing tests; a test you break is yours to fix, never to delete. New checker rules get a poison probe (a program the rule must refuse) and a positive probe.

Use only tactics and lemmas that exist HERE: `split` (never `split_ifs`), `omega`/`decide`/`simp`/`rfl`/`rw` are available, `norm_num`/`ring_nf` are NOT. Read the exact helper definitions (`Wort.lean`, `Ganzzahl.lean`, `Stapel.lean`) before stating facts about them.

A green proof of a wrong definition is a finding, not a result: hardware facts (sign vs zero extension, byte lengths, encodings, flag effects) must match the architecture, checked against the supplied hardware references, not against the proof shape. State effects against the existing canonical definitions (e.g. `Stapel.lean` push); never duplicate a model the tree already has — if the canonical definition cannot be reused as stated, report it.
17. VENDOR NEUTRAL. The model holds on every x86-64 CPU, Intel and AMD. Behaviour that either vendor calls undefined or model-specific stays FREE (model all allowed results; never pin one observed value), and no AMD provenance is claimed without an AMD manual in your clone.
