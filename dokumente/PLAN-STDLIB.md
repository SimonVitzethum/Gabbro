# The standard library, native in Gabbro: the plan, and what is built

*Simon's decision, 2026-09-16: **everything a standard library does, except networking, files, graphics and
windows, is to be written in Gabbro itself.** Not as `extern` declarations with a named assumption, not as C behind
a border: as Gabbro modules the checker checks and the goal theorem covers. Status checked against the tree on
2026-10-17: the two blockers are decided, **none of the library layers L1-L6 exists yet under `bibliothek/`**; what
exists there are the OS bindings (section 6).*

The decision came out of a measurement: a Linux firewall was written in Gabbro (7,494 lines in eight modules, outside
this tree) and it ran: a netlink socket opened, memory mapped, the worker parked in `recvfrom`, every system call
issued from Gabbro. What it kept hitting was not the language's semantics but its empty shelf: no memory copy, no ring
buffer, no queue, no timer wheel, no strings, no hash, no sort.

## 0. Scope

**In**, because a systems program needs it on every page:

| Layer | What | Built? |
|---|---|---|
| **L1 primitives** | copy / set / compare over table slices; endianness; bit operations (count, scan, mask); saturating and wrapping helpers; min / max / clamp; integer `log2`, `sqrt`, division helpers | **not built as a library.** The operator forms exist in the language (wrapping `+% -% *% <<%`, saturating `+%|`, lane 88; `SYNTAX.md`); byte helpers (`u16_gross`, `u32_klein`, ...) live in the network stack's own library, outside this tree. No shared `bibliothek/` module |
| **L2 containers** | ring buffer (SPSC and MPSC), stack, bitset, fixed hash map and set, sorted array with binary search, index-linked list, timer wheel | **not built.** `beispiele/185-ringpuffer.gab` is a checker example of ring-buffer pop semantics (a corpus witness, not a library module); the pool form (`table ... insert/remove`) and arenas (`PLAN-DYNAMIC.md`) are language features |
| **L3 algorithms** | sort (insertion, heap) over a fixed table; binary search; hashing (FNV, sip-like); CRC and Internet checksum | **not built** |
| **L4 text** | byte strings over tables: length, compare, find, split; number formatting and parsing, both without allocation | **not built as a library.** Bounded strings (layout, literals, `lenof`, index, copy, concat, lexicographic compare) are a language form the LLVM backend lowers |
| **L5 time and concurrency** | monotonic clock; durations; sleep; the ticket lock; futex wait/wake; sequence lock; epoch-style reclamation | **partly, as runtime and bindings, not as a library:** the ticket lock is generated by the compilers and written once in Gabbro as `laufzeit/sperre.gab` (the shape of the ticket lock of the removed C line, tag `archiv/c-emitter-2026-10-17`; a runtime sample whose refusals were findings); futex wait, `clone`, sched-yield and the thread exit are gates in `bibliothek/linux/linux.gab`; clock, sleep, sequence lock and epoch reclamation are not built |
| **L6 randomness** | a counter-based PRNG, and entropy from the kernel through a system call | **not built** (a `getrandom` gate would be a binding item) |

**Out, by Simon's line:** networking, files, graphics, windows. Those are I/O against a world with its own rules; they
stay system calls at the program's own border, declared where they are used.

*There is no hidden standard library behind this line: Gabbro has no libc, no built-in socket, file or TLS layer, and
nothing is linked at run time. A program, or a binding library such as `bibliothek/linux/`, performs every OS call itself
through `syscall` items with their own contracts. An HTTP or TLS server is therefore not impossible, only not built in:
it is written in Gabbro over raw system calls and checked like any other code.*

*Note what "out" does NOT mean: the firewall's netlink work stays in the firewall. The library gives it the ring buffer
and the checksum, not the socket.*

## 1. The first blocker: composition across units (largely lifted)

**Measured 2026-09-16, in the firewall:** a module that wanted to read another module's table was refused (`M119`), and
the only workaround was an `extern fn` mirror with a C-identical prototype plus a named assumption per crossing. The three
questions it forced:

1. **What does a unit see of another unit?** Decided and built: public functions with their contracts through a derived
   `.gabi` interface (`gabbro abi`, `gabbro link`, `--with L.gabi`); `pub` is the closed export hull (`N038`), the module
   boundary `N025`; an interface head carries types and contracts, not bodies. (`BUILD-SYSTEM.md`: the edge, built and run.)
2. **Who checks the crossing?** The checker, over both units: `gabbro link A.gab B.gab` reads each unit's DERIVED
   interface, effects are derived across the border, ranks travel; an `assume` does not cross (a decision, not a hole).
3. **What does the goal theorem say about two units?** The model half is proved: `GabbroZielVerbund` (Opus agent E; OFFEN
   O28, with its remainder). The refinement half for separately compiled units (linked bytes refine the linked program) is
   open and belongs to translation validation.

So a library module can now be a real dependency of a program. What stays open is O28's remainder, not the ability to write
the library.

## 2. The second blocker: the generic question (decided: no type parameter)

A ring buffer holds *something*; Gabbro's tables are concrete (`count` fixed, the slot record written out). A ring of `u32`
and a ring of a four-field record are two modules. The counter lane measured what that costs when it had to write 256
scalars instead of one array: **5,136 lines instead of 287, and 1,797 ops instead of 11.**

Three routes were weighed:

* **(a) per-type instantiation by hand** (honest, multiplies the library by the number of element types);
* **(b) a generator** that writes the module from a description, the result checked as any source, with a guardian that the
  generated file is what the generator writes (the precedent: the retired `pruefe-genlean`, 2026-10-17);
* **(c) a type parameter in the language**: `Ty` is deliberately non-recursive, and a parametrised table would be a new
  shape in every pass and in `Akzeptiert`. The product-former lane refused this kind of change on measurement (OFFEN O15,
  priced and REJECTED for zero corpus use), and the same rule applies: it must pay for itself in programs.

**Current position:** (c) is rejected; (a) and (b) stand. Which of the two is measured when the first container is written
(how many element types does a kernel actually need).

## 3. What every library item owes

1. **A contract**: `requires`/`ensures` that say what it does, not how.
2. **A proof obligation discharged once, not per user**: the item's own `ensures` proved against the model, so the caller
   inherits it. That is the whole economic argument of the language, and the library is where it is true or empty.
3. **A cost bound** the checker holds it to (a scheduler needs it).
4. **A poison probe and a positive probe**, like every rule in this tree.
5. **The named absence** where an item cannot carry what a C library would: no allocation, no unbounded recursion, no growth.

## 4. Order

1. Composition (section 1): done to the point of use.
2. The generic route (section 2): decide (a) or (b) at the first container.
3. **L1 primitives**, because everything else stands on them and because the bound checks live there.
4. **L5 concurrency** next, not last: the runtime needs the lock and the futex.
5. **L2 containers**, starting with the ring buffer and the timer wheel (what the firewall and any driver need first).
6. **L3, L4, L6** after that, in the order programs ask for them.

## 5. Where it lives

`bibliothek/` in this tree, one module per file, with its probes beside it, and a guardian that every module checks and
compiles through the same instruments as the corpus. **It is not a separate project**: a standard library not measured by
the same instruments is a promise, not a library.

## 6. What is in `bibliothek/` today (bindings, not the library above)

| Path | What it is |
|---|---|
| `bibliothek/linux/linux.gab`, `linux-aarch64.gab` | the Linux x86-64 and AArch64 bindings a hosted program takes off the shelf: the report channel (`gabbro_os_melden`, `_ende`, `_schreibe`, `_schreibe_zahl`), storage (`gabbro_os_reserve`, `_commit`, `_seitengroesse`), page return (`_seiten_zurueck`), the lock hand-over (`_nachgeben`), the thread gates (`_klon_tor` stack gate, `_klon_flaggen`, `_faden_ende`, `_warte_wort`), each a `syscall` item with its contract and a named assumption/falsifier |
| `bibliothek/linux-kmod/linux-kmod.gab` | the kernel-module binding (`_printk`, `panic`, the thread start and join sleep) |
| `laufzeit/sperre.gab` | the ticket lock written in Gabbro (a runtime sample) |

None of it is a data structure or an algorithm; it is the border the program owns. A binding keeps the user-logic
obligation: nothing in the checker, model or compiler knows an operating system.
