## Design (why this shape)

- The task asks for call entry/return with the ACTUAL `rho`/`v` at their
  place, generated by a machine (not free wrapper data as in `ContrLauf`).
  The machine reuses the `GenSchritt` ideas (shared `Speicher D`, per-thread
  traces, `GenFrei`-style scheduler rule for `nimmt`) and the `VertragOrtB`
  contract shape (`ReqAmEintritt`, `EnsAmRueck` with actual `rho`, `v`, `s0`).
- Frames hold real `Endblock` residues under the callee contract
  (`vertragVon D f`), so leaf steps run through `execStmt` with `keinRuf`
  (memory moves on writes by construction). The step relation does NOT gate
  on contracts: `VertragAmOrtMaschineD` is a predicate ON generated runs.
- Hard-won Lean facts (so the next attempt does not re-pay them):
  (a) residue types must mention `(M.faeden f).kopf.f` directly -- an
  outer `V` binder plus a `hV : V = ...` equation does NOT rewrite inside
  `Stmt`/`Endblock` indices at constructor-application time;
  (b) `Endblock.cons (.call ...)` needs the tail at `nach D g Λ`
  (the call's post-resources), not at `Λ`;
  (c) `induction h with` on the log invariant fixes stack/log indices per
  case -- the workable pattern states the goal with an inner `∀` (as in
  `rufLogPasstD_gedeckt`), or proves a membership lemma first;
  (d) `cases htail with | eintritt s2 ...` needs EXACTLY the constructor's
  explicit arity (7 for `eintritt`, 6 for `rueck`); shadowing outer binder
  names produces cascading `unknown identifier` errors;
  (e) `RufSchrittD` constructor arguments start with `(M)(f)` -- `P O passes`
  are family parameters, not constructor binders;
  (f) `.add` computes result ranges (`.int 0 5 + .int 0 1 = .int 0 6`), so the
  witness `erg` is `some (.int 0 6)` while params stay `.int 0 5`;
  (g) `RufPasst.hw` over `fun _ => false` closes by `rw [rfl-lemma] at ht`,
  not by `decide`/`simp` (open terms block both).

a call and its return" is satisfied here by a run from a caller machine
rather than from `RufStartD` -- the start state logs entries without pushing
