RUNSPEED: Stage-0 runner execution speed (measured 2026-11-13)
=====================================================================
Branch: t3/stage0-runner-throughput. Probes: speed/speed_{a,b,c,d}.gab
(small defaults, exits 243/10/4/10, all compile and hand-verified).
Scaled front-end fixtures and the repeat-driver live only in scratch
(not committed); their construction is described in section 5.

Machine: 31 GB, load 2.5-4 during measurement (another agent was
measuring compile time concurrently, so timings carry ~+-30% noise;
minima and slopes are reported, never single runs). Every run alone,
inside `systemd-run --user --scope -q -p MemoryMax=6G -p MemoryHigh=5G
-p MemorySwapMax=0`. Scope+loader startup floor is ~6-9 ms per run;
rates below come from SIZE SLOPES, not single timings.

1. What the runner is, and what the lowering emits
--------------------------------------------------
S0IR: one instruction = 16 bytes (opcode byte + three i32 fields at
pc+4/+8/+12, sign-extended). A thread is pc+fp; slot i = word at fp+8i.
Semantics: runner/Runner/IR/Step.lean (`op`, `step`, `bin`, `ret1`).

Execution is a direct interpreter loop ("threaded dispatch"): every
handler in the generated runner (runner/runner.s, generated by
runner/Runner/Prog/Code.lean `handler`/`binH`/`dispatch`) ends with
`movzx rax, byte [r12]; jmp [r14+rax*8]` (r12 = IR pc, r13 = IR fp,
r14 = 256-entry table; no opcode handler -> ud2). Dispatch proper =
2 x86 instructions; each handler re-reads its fields and slots in the
semantics' order and writes last.

Hot-path x86 counts per IR instruction (read off runner/runner.s):
const 7, mov 7, add/sub 10, mul 10, and/or/xor 10, cmp+setcc 12-13,
sdiv/srem ~10+idiv, udiv/urem ~11+div, ld (op15) 9, st (op16) 9,
lea 7, jmp 3, brz 5+3, call (op20) ~10, ret (op21) 3, cas/sys 10+.
Roughly half the executed x86 is dispatch + field/slot loads.

Source operation -> IR instructions (read off stage0/Stage0/Senke/,
`lowE`/`lowB`/`lowS` and the `*C` emitters; D = image bytes / 16 on
pairs of tiny programs differing by one statement, same tables):

  source op                              IR emitted            by
  literal const                          1 (const)             lowE .lit / wordConst (Ausdruck/Aggregat/Hilfena)
  local read (1 word)                    1 (mov)               copyWords (Kopie) -- D: +1
  `let x = <e>` (bind)                   cost(e) + 0           lowB .bind (in place) -- D: `let b=4` unused = +1 (the const)
  `a + b` on locals                      3 (mov,mov,add)       lowE add / bin2 -- D: +3
  `x = a + b` (assign)                   3 + 1 (copy)          lowS .assignVar + copyWords
  table slot read, const idx, 1 word     8 (1+4+3)             slotValueC/cellAddressC/loadPointerSpan -- D: +8
  table slot write                       child + 7             slotStoreC/storePointerSpan (4 addr + 3 store)
  call, 2 args                           args + 4 tail         callC/callTailN: const 1, depth-1, addr, call
  callee entry (executed)                4 guards + requires   lowFun/guardC (2x [brz,jmp], stopC skipped)
                                           + 2xparams relocate + snapshots
  normal return                          copy + ens + 4        retC/publishC ([copy, const, mov, ret])
  `if c then t else e`                   cond + 1 brz + t      lowS .ite
                                           + 1 jmp + e
  guarded narrowing `eng` (scalar)       ~84                   narrowC = ce + wideExtendC + wideOutC
                                                                 + brz + err-epilogue -- D: +84 (!)
  `traverse` per iteration               ~8 + body + 2x invar.  travC/travCode: head (invariant + brz,mov,
                                         const,cmp,brz) + body + (const,add,jmp);
                                         invariant re-evaluated in leave part
  call-depth counter                     2 in caller + 4 here  callTailN + guardC; budget
                                         depthOf = (Ks-FB)/L - 1, Ks = 2^19 (IRBild.lean)
  per-loop fuel                          NONE for traverse     count-bounded; retry/forever take
                                         passes/budget (Schleifen/Code)

Confirmed by image-size difference (D): bind +1, local add +3,
const-index slot read +8, scalar narrow +84. The narrow number is
real: even same-width u32 narrowing goes through the multiword
wideExtendC/wideOutC kernels (WideInt/KernelCode).

2. Measured throughput (exit codes hand-computed for small inputs)
------------------------------------------------------------------
(a) pure arithmetic recursion (speed_a; inner(1000) + outer K):
    K=2000/5000/8000 -> 0.43/1.03/1.65 s, exits 32/80/128 (=K*1000%251).
    Slope: 4.8-4.9M inner iterations/s (~0.2 us/iter), linear.
    Depth stop (exit 105): works at 11375 nested calls, fails at 11500
    (this frame shape). Removing the result narrow + add saves ~30%
    (1.65 -> 1.15 s at K=8000), so one scalar narrow is ~1/3 of a level.
(b) table scan, sum one field (speed_b, fill + scan traverses):
    N=50000/200000 -> ~10/~26 ms, exits 51/204 (=N%251). Smaller N all
    at the startup floor. Slope: ~53 ns/slot-visit -> ~19M visits/s.
(c) lexer-style byte scan (speed_c: fill 97+(i%3), classify call +
    if-chain + count): N=20000/60000/150000, exits 141/171/51
    (=hits%251, hits=N/3). Slope: ~92 ns/slot -> ~11M slots/s.
(d) call-heavy chain top->mid->leaf (speed_d): N=20000/60000/150000,
    exits 171/11/153 (=N%251). Slope: ~138 ns/slot -> ~7M slots/s ->
    ~21M calls/s (~48 ns/call).
(e) front end (stage0/proben-compiler: srcbuf+lex+parse+front, 155 B):
    unmodified: exit 87 (= 52 toks + 35 nodes, cf. FINDINGS.txt),
    ~7-9 ms/run (startup floor). Scaled fixture (input text repeated
    k times in scratch; tables/fuels/ranges scaled x1/x2/x4; duplicate
    fn names accepted by the checker): k=1/2/4 (155/310/620 B) ->
    exits 87/173/345(observed 89 = 345 mod 256), all ~8 ms (floor).
    k=8 (1240 B, 16 fns) -> exit 105: call-depth exhausted.
    Repeat-driver (scratch copy + per-module zero_state resets +
    drive(R) recursion over run_once; exit 87 iff all R runs return
    87): R=200/500/1000/2000 -> 49/105/187/362 ms, exit 87.
    Slope: ~175 us per 155 B -> ~0.89 MB/s through lex+parse+check.
    IR per iteration implied: ~90k IR (~580 IR/byte).

Implied IR execution rate: (a) ~0.5-1.2G IR/s (narrow mix dependent),
(b) ~0.4G IR/s (urem/div-bound: every visit does acc%600000). The
interpreter dispatches on the order of 10^9 IR instructions/s; the
end-to-end gap to native is the lowering expansion factor.

3. Ratio to native
-----------------
Baseline 10^9 simple operations/s (no C compiled in this repo):
  (a) 4.8M iters/s x ~5 ops      ~ 24M ops/s   ~1/40 native
  (b) 19M slots/s x ~6 ops       ~110M ops/s   ~1/9  native
  (c) 11M slots/s x ~8 ops       ~ 90M ops/s   ~1/11 native
  (d) 21M calls/s x ~10 ops      ~200M ops/s   ~1/5  native
Per IR instruction the runner is ~1/2 native speed; each source op
costs 3 (add) to ~84 (narrow) IR instructions.

4. Self-compilation estimate (criterion: 500k lines, self-hosted
   compiler compiled by Stage 0 and executed by the runner, < 1 hour)
--------------------------------------------------------------------------
Assumptions: S1 500k lines ~= 22 MB (45 B/line, Gabbro is verbose);
S2 measured toy front-end rate 0.89 MB/s applies per source byte;
S3 a full compiler is F = 10-50x the work of its front end per line
(task range: lowering, optimization, emission, validation);
S4 real-compiler table sizes force wide ranges (narrow ~84 IR vs ~10
scalar): extra ~2x on narrow-heavy code.
  Front end alone: 22 MB / 0.89 MB/s ~= 25 s.
  Full self-compile: 25 s x F (x2 wide-range) = 250 s (~4 min, F=10)
  to 2500 s (~42 min, F=50 with S4).
Verdict: BORDERLINE. Under one hour is plausible at the optimistic
end (F <= 20, small ranges) and out of reach at the pessimistic end.
Structural risk (measured): the call-depth budget (Ks = 2^19) is
already exhausted by 16 toy functions / 1240 bytes (exit 105 between
k=4 and k=8), so a 500k-line compiler cannot be one unit -- it needs
separate compilation (GabbroZielVerbund) or a bigger Ks.
Largest avoidable costs, with shares:
  1. scalar `narrow` through the wide multiword kernels: ~66-84 IR
     per check, ~1/3 of recursion-level time (measured); a 1-word
     fast path would remove most of it;
  2. per-call entry (2x guardC + requires + relocate + snapshots) and
     return epilogue (~20-30 IR even for `pure` leaves);
  3. traverse head (~8 IR) + invariant evaluated twice per iteration;
  4. interpreter dispatch proper (~2 x86 + field loads per IR, about
     half the executed x86); urem/div in `%`-bounded accumulators
     (table-scan loops are div-bound, not dispatch-bound).

5. Exact commands and the scaled fixtures
-----------------------------------------
cp stage0/.lake/build/bin/stage0 .scratch-m/stage0
cp stage0/.lake/ir/runner .scratch-m/runner
.stage0 --ir A.gab [B.gab ...] OUT.img; echo $?   # compile, exit 0
.systemd-run --user --scope -q -p MemoryMax=6G -p MemoryHigh=5G \
    -p MemorySwapMax=0 .scratch-m/runner OUT.img; echo $?
start=$(date +%s.%N); ...; end=$(date +%s.%N)     # wall time
Size calibration: pairs c0..c7 in scratch (see section 1, D column).
Scaled front end (scratch .scratch-m/scale/): bytes 0..154 of TEXT
extracted token-wise (',' protected), repeated k times, re-emitted 8
per line as numbers, zero-padded to 160k; bounds scaled uniformly by k
(positions 158/159/160 -> x*k -2/-1, toks 64k, nodes 96k, fuels, syms
32k), with three non-uniform fixes: lex emit-full sentinel 64 -> 64k,
node payload fields b/c 255 -> 1024k-1 (token start/len exceed 255),
node-id channels -> 128k-1 (k>=4) and checker id params -> 1024k-1
(they receive node_b/c outputs); k=4 main return widened (345 > 255).
Repeat driver (scratch .scratch-m/drv/): pristine 4 files +
zero_state reset fns appended per module (reset is a reserved word in
statement position: `reset();` fails to parse with "name expected")
+ run_once (old main) + drive(R)/main recursion; exit 87 validates
all R iterations. Traverse bodies cannot transitively write
cross-module statics (export gate refuses; no probe covers `::` in
touches) -- hence recursion, not traverse, drives the repetition.
