FINDINGS: what Stage 0 refused in compiler-shaped Gabbro source
================================================================

Unit: stage0/proben-compiler/ (srcbuf.gab, lex.gab, parse.gab, front.gab),
one module per file (`srcbuf`, `lex`, `parse`, `front`), compiled as one unit
with `stage0 --ir`. It lexes a fixed 155-byte program (fn, let, if/else, return,
calls, precedence, both comment forms), parses it into a 35-node AST in
tables, runs one scope-aware checking pass, and returns token count plus
node count. Measured: exit 87 (52 tokens + 35 nodes) on success; 255 on
lexer failure, 254 on parse failure, 252 on checker failure. All three
failure exits were verified by mutating one byte of the fixed text each
(unterminated block comment -> 255, `let = ...` -> 254, call to `maz`
-> 252); re-checked after every rewrite round below, most recently after
the module split. The 253 exit (integer literal wider than the value field)
is a dead defensive branch on this text and was not triggered.

State 2026-11-13: the forms the compiler has gained since this file was
written were tried on this unit, one kind at a time, compiling and running
after each kind. Exit stayed 87 throughout; 255/254/252 were re-checked at
the end. Counts below are sites in this unit (1.2k lines); the (judgment)
frequency notes for a real compiler of several hundred thousand lines are
unchanged from before.

1. Write rights do not cross module boundaries -- GONE
   The split the entry wanted is in place: `module srcbuf`, `module lex`,
   `module parse`, `module front`, one per file. All 115 cross-module calls
   are qualified (`srcbuf::fill()`, `lex::tok_kind(ti)`, `parse::node_a(ni)`,
   ...). Readers need no claims (a `pure` caller may call a reader anywhere,
   and reads through calls need no effect entry -- measured). Writers are
   claimed with qualified effect places in `main` (8 foreign carriers):
   `writes srcbuf::src.slots, writes srcbuf::srclen`,
   `writes lex::toks.slots, writes lex::tok_used, writes lex::lex_err`,
   `writes parse::nodes.slots, writes parse::node_used, writes parse::parse_err`.
   Foreign record types project without imports (`u.node`, `u.ok` on a
   `parse::POut` in `front::main` compile and run). The milder `use` +
   `pub` variant compiles too (scratch probe only, the unit keeps qualified
   calls). No `pub` items, no `use` in the unit. 0 sites remain.

2. No `while` loop -- STILL REFUSED, unchanged
   Wanted:
     while pos < len {
         pos = pos + 1;
     }
   Refusal:
     stage0: assignment or call expected
   36 `decreases` fuel recursions remain (8 front, 7 lex, 19 parse, 2 srcbuf);
   every scan and worklist is still fuel recursion.
   Frequency (judgment): HIGH.

3. `return f(...)` from inside a branch -- PARTLY
   47 sites used `let q = f(...); return q;` (16 in lex, 18 in parse,
   13 in front). 34 are direct `return f(...)` now. 13 remain in parse.gab:
   a directly-returned call in a branch still refuses a RECORD-FIELD
   projection as an argument (`r.pos`, `l.node`, ...), even when every
   other argument is plain:
     stage0: value without G form
     note: elaboration: function pick: value without G form (statement 1 of 1: if)
   (scratch probe `retcall-field.gab`: `return nxt(r.node, r.pos);` in a
   branch; the top-level `return f(r.node, r.pos);` and the branch
   `return f(k + 1);` both compile, and binding one field to a local does
   not help while any projection remains.) The 13 sites keep the old shape.
   Frequency (judgment): HIGH.

4. No flow-sensitive narrowing from conditions -- ACCEPTED BY THE COMPILER,
   0 SITES CONVERTED
   Guard narrowing compiles as documented (`if i < 10` indexes, `if n >= 1`
   subtracts, local-minus-local under `if a >= b`, facts after an ordering
   guard whose then block returns). In this unit none of the 117 code
   `narrow` statements could go: every bound here comes from an EQUALITY
   guard (`if k == 0 return`, `if pos == n return`, `if e == 255 return`,
   kind dispatch), which narrows nothing in the else/after direction
   (scratch probe `guard1b.gab`: `if k == 0 { return 0; }` followed by
   `T.slots[k - 1]` is refused with `stage0: value without G form`), or
   the `narrow` doubles as validation (its else arm sets an error flag or
   returns failure for inputs that really are out of range). Two `narrow`
   statements disappeared with the deleted `sym_lookup_rec` (entry 13);
   net 115 code narrows remain. The `narrow`-before-arithmetic shape stays
   the idiom wherever the guard is an equality or a validation.
   Frequency (judgment): HIGH.

5. `narrow` does not apply to record fields (or table slots) -- STILL REFUSED,

   Refusal:
     stage0: stmt without G form: trim

6. Character literals do not exist -- GONE

   Frequency (judgment): MEDIUM.

7. No wildcard match -- STILL REFUSED for u32 dispatch, unchanged in the unit

     stage0: name expected
   (scratch probe `match-u32.gab`). All ~70 kind-code `if` chains remain

8. No tuples -- STILL REFUSED, unchanged

   Refusal:

9. `bool` record fields do not survive as truth values -- GONE

   The u32-flag idiom went with it: 3 error statics (`lex_err`,
   `parse_err`, `check_bad`) are `bool`, and 10 flag functions return

   `== 1` flag tests remain (only kind-code and 255/33-sentinel
   comparisons, which are numbers).
   Frequency (judgment): LOW.

10. A bare constructor or a computed array index cannot go straight
    into a table slot -- PARTLY
    The one live copy-through-local (`let v = TEXT[k]; src.slots[k].b = v;`)
    is now `src.slots[k].b = TEXT[k];` (measured probe shape). A COMPUTED
    slot index is still refused even when an ordering guard makes it
    in-range:
      stage0: value without G form
      note: elaboration: function f: value without G form (statement 1 of 1: if)
    (scratch probe `slotidx.gab`: `if k >= 1 { return T.slots[k - 1].k; }`;
    the `let d = k - 1; return T.slots[d].k;` shape compiles). No remaining
    site needs it; the unit indexes slots with plain locals only.
    Frequency (judgment): LOW-MEDIUM.

11. `const` of string type has no form at its use -- PARTLY
    Named string constants compile and index (`const Q : string max 8`,
    `Q[0]`), but they cannot hold this unit's text: string literals have
    NO escapes (`"a\nb"` indexes as 97, 92, 110, 98 -- the `\n` stays two
    characters, scratch probe `s7.gab` runs 92 for `T[1]`) and a literal
    newline in a string is refused (`stage0: lex`, scratch probe `s10.gab`).
    Byte 10 is therefore inexpressible in a string constant, so the text
    stays a `u32` array -- now written with 151 character literals
    (`'\n'`, `' '`, `'f'`, ...) plus 5 numeric zero pads, byte-identical to
    the old numbers (verified by decoding). The `TEXT[k]`-through-local
    copy is direct (entry 10).
    Frequency (judgment): LOW-MEDIUM.

12. No equality on tagged values -- GONE (vacuous)
    Tagged equality compiles (newest probe); the unit has 0 sites (kinds
    are u32 codes and stay so). Nothing changed.
    Frequency (judgment): LOW.

13. `traverse` with a call-derived narrowed value plus `next` -- GONE
    `sym_lookup_rec` (downward fuel recursion) is deleted. `sym_lookup` is
    a `traverse i over slots of syms by unvisited touches reads syms.slots`
    whose body calls `cmp_span`, skips dead slots with `if i < u`, and
    overwrites `found` on every hit, so the innermost declaration wins;
    reads through calls need no extra claims (scratch probes
    `trav1..trav4.gab`). 1 recursion removed, 0 `traverse` workarounds left.
    Frequency (judgment): LOW.

Forms the unit needed that worked without any workaround
--------------------------------------------------------
- One module per file, compiled as one unit (entry 1).
- Qualified reads across modules need no effect claims; writers are
  claimed with qualified places in the caller.
- Recursion with an explicit fuel parameter and `decreases`, direct and
  mutual (lexer skip helpers, expression levels <-> primary).
- `traverse ... by unvisited` with a call in the body, a live-prefix bound
  and last-hit-wins shadowing (entry 13).
- Guard narrowing where the guard is an ordering comparison (entry 4 probes;
  the unit's own arithmetic sits under equality guards).
- Character literals in comparisons, narrow bounds, array elements and
  arithmetic (entries 6, 11).
- `bool` fields, params, returns, locals, `!` and `&&`, `static mut bool`
  (entry 9).
- Direct in-branch `return f(...)` for plain arguments (entry 3); direct
  array reads into slots (entry 10); named string constants for
  newline-free text (entry 11); tagged equality (entry 12, unused).
- Records as values, parameters and function results, including a `bool`
  field; constant arrays with literal and variable indexing; `option`-free
  33/255-sentinel searches; four-parameter functions; `if` chains and
  `else if` shapes; `let mut` locals; static mutable scalars, tables and
  their effects. Only field/slot `narrow` (entry 5) and `bool` in
  conditions on u32 flags (entry 9, gone) ever failed.
- `narrow ... else` with value returns, bare `return;` in void functions.
- No `costs` clauses anywhere: all functions omit them and compile.

Not tried
---------
- Substring or slicing syntax (no known spelling attempted).
- `&&` / `||` over calls, division (a `Div` node kind is parsed but no
  division executes), shifts and bit operations.
- Function pointers, locks/atomics, `retry`/`forever`, `spec`/`impl`
  contracts, `dyn`, formats, devices, strings beyond literals.
- `use` imports in the unit (compiles in a scratch probe; the unit keeps
  qualified calls).
- Separate compilation and linking of units.
- Anything quantitative: no compile-time or run-time measurements.

NEW findings (all with a minimal source text)
---------------------------------------------
N1. FIXED — stage0/proben-ir/branch-return-fields.gab.
    Original finding: A call returned from a branch refuses record-field arguments.
    Even one record-field projection among the arguments fails, at the top
    level the same call compiles, and binding one field to a local does not
    help while any projection remains (entry 3 remainder).
    Minimal (`retcall-field.gab`, refused with `stage0: value without G
    form` + `note: elaboration: function pick: value without G form
    (statement 1 of 1: if)`):
      type POut = { node : u32 in 0 .. 255, pos : u32 in 0 .. 64, ok : u32 in 0 .. 1, };
      impl fn nxt(n : u32 in 0 .. 255, p : u32 in 0 .. 64) -> POut
          effects { pure }
      {
          return POut(node: n, pos: p, ok: 1);
      }
      impl fn pick(r : POut, k : u32 in 0 .. 1) -> POut
          effects { pure }
      {
          if k == 1 { return nxt(r.node, r.pos); }
          return r;
      }
N2. FIXED — stage0/proben-ir/slot-computed-index.gab.
    Original finding: A computed table-slot index is refused even when in range (entry 10
    remainder). `let d = k - 1; return T.slots[d].k;` compiles.
    Minimal (`slotidx.gab`, refused with `stage0: value without G form` +
    `(statement 1 of 1: if)`):
      table T count 160 { slot { k : u32 in 0 .. 31, } }
      impl fn f(k : u32 in 0 .. 159) -> u32 in 0 .. 31
          effects { reads T.slots }
      {
          if k >= 1 {
              return T.slots[k - 1].k;
          }
          return 0;
      }
N3. FIXED — stage0/proben-ir/guard-equality.gab.
    Original finding: Equality guards do not narrow; only ordering guards do. After
    `if k == 0 { return ...; }` the compiler knows nothing about `k`
    (`guard1b.gab`, `T.slots[k - 1]` refused); after `if k >= 1` the
    subtraction compiles (`guard7.gab`). The `after` probe shape works for
    the same reason. Real parser code guards almost everything with
    equality, which bounds the worth of entry 4.
    Minimal pair:
      if k == 0 { return 0; }
      return T.slots[k - 1].k;   // refused: stage0: value without G form
      if k >= 1 { return k - 1; } // compiles
N4. FIXED — stage0/proben-ir/string-escape.gab.
    Original finding: String literals have no escapes. `"\n"` is backslash + `n` (two bytes;
    `T[1]` of `"a\nb"` runs 92), and a literal newline inside a string is
    refused (`stage0: lex`). Byte 10 -- and hence any multi-line text --
    cannot live in a string constant (entry 11 mechanism).
    Minimal (`s7.gab` runs 92; `s10.gab` refused with `stage0: lex`):
      const T : string max 4 = "a\nb";   // T[1] == 92, not 10
N5. OPEN — the loader is modelled; an assembly-only fix is not valid.
    Missing images still cause SIGILL (shell status 132), without a runner
    diagnostic. Stage 0 itself leaves no image after a failed compilation.
    Check the compilation result before invoking the runner.
    The loader already tests a negative open result before using the fd;
    its error branch deliberately executes ud2. The actual loading calls
    are open(2), lseek(8, SEEK_END), and mmap(9), not fstat or read. Negative
    lseek results, zero lengths, and mappings other than IMG also reach ud2.

    Model boundary: runner/Runner/Prog/Code.lean defines ld1, ld2, ld4,
    ld5 and loaderI; Prog/Elf.lean includes them in the emitted ELF bytes.
    Beweis/Lader.lean explicitly models these failures as .fault in
    loadTree/t2/t3 and proves loader_ok and runner_entry_tso/sc over them.
    runner.s is the generated address listing (Prog/Liste.lean), not an
    as/ld input. Haupt.lean writes the ELF directly; runner-cpu.py checks
    that the committed listing equals the generated listing. No external
    assembler or linker command for runner.s exists in the build path.
    Per the task's model-boundary restriction, no modelled code or listing
    was changed; N5 must not be marked fixed.

    Required model change: check argc before argv[1], replace loader fault
    branches with write(2, "runner: <what>: <path>\n", ...) and
    exit_group(127), and prove the resulting request trees in Lader.lean.
    Define a missing-argument path placeholder. Check file length before
    header access (16-byte header plus a complete 16-byte first instruction)
    and reject address-range overflow before mapping or computing bounds.
    Header bytes 0..7 contain the initial absolute frame pointer, assigned
    to r13 and later used for slot addresses: check alignment and that at
    least its first word lies inside the image. Bytes 8..15 are reserved
    zero by the writers and ignored by the loader. Entry pc is fixed at
    IMG+16; there are no magic/version/code-size/frame-size header fields.
    These checks cannot establish bounds for all subsequent IR accesses.
    A file-backed mmap also permits later SIGBUS on concurrent truncation;
    a complete load-error guarantee needs a private anonymous snapshot with
    checked reads (negative results/early EOF), reflected in loadTree.
    Keep handler/dispatch instruction lists unchanged, regenerate the ELF
    and listing, and recheck placement/layout and entry theorems. The existing
    syscall instruction can express the diagnostics without a new ISA family.
    Main's result is passed through IR sys to exit_group (Senke/Start.lean);
    no status is reserved from 0..255. Use the requested fallback 127, which
    can still coincide with a program result; stderr identifies a load error.

State 2026-11-13 (evening): input-length recursion replaced by loops
---------------------------------------------------------------------
All 36 `decreases` fuel recursions over the input length are gone (8
front, 7 lex, 19 parse, 2 srcbuf); every scan and worklist is a
`traverse` sweep now, so the call depth is bounded by the nesting depth
of the parsed program instead of its length. Entry 2 (`while` refused)
stands: the sweep is the accepted shape, documented with its refusal
trail in DEPTH.txt (R1-R8). What the sweep needs beyond the old
recursion, per loop: a table domain (own or cross-module qualified --
both compile), a plain-`u32` frozen cursor copy per visit, redundant
direct ordering guards (one bounded operation per guard), a helper call
for constant-array reads (R2), bind-to-local-first for call results
into slots (R1) and for mutated-slot indexes (narrowed immutable copy),
and `decreases`+fuel kept stale for cycle consistency (R5). Chain
loops patch the previous tail: field `b` for Arg (14) and Seq (12),
field `c` for Param (19) and If (10) -- patching the wrong field
truncates the chain and the checker then passes vacuously (found via
the 252-mutant, DEPTH.txt B1). Observable results kept exactly: exit
87 on the 155-byte text; 255/254/252 re-verified by the same one-byte
mutations (plus def-side `maz`, plus a custom else-if/3-arg text with
exit 108 identical on old and new code). Largest running input went
from 155 bytes (105 already at 310) to 19840 bytes (k=128); k=256
stops with 105 again, proven width-driven (the k=1 text also stops
under KMAX=256 bounds), not length-driven -- see DEPTH.txt sections
3-5 for the tables, the refusal evidence for O18, and the exact
commands. Frequency notes for a real compiler: every cursor loop pays
the guard/freeze/patch verbosity above (HIGH, same class as entry 2);
the chain-link field rule (B1) deserves a checker-side note (a
truncated chain is a silent pass, only negative tests catch it).
