### 1.3 The 32-bit sweep found no defect, and that is the claim

`gcc -m32` and `clang -m32` over all 121. Six units fail the house gate at 32 bits and pass
at 64:

* **four are `-- erwartet: cc` reverse probes** (`gift/414`, `probe-eintritt-{parameter,
  privat,zwei}`) — they are meant to fall, and they fall at both widths;
* `beispiele/36-asm.gab` — inline `asm` with x86-64 operand constraints. `asm` is a named
  trust hole that travels in the certificate; it is architecture-bound by construction;
* `messung/proben/probe-zwei-gibibyte.gab` — a 2 GiB table, which genuinely exceeds i386's
  maximum object size. **The C compiler is right and the declaration is not portable**, which
  is a true statement about the program rather than about the lowering.

> **Nothing else moved between 64 and 32 bits.** The strict flag set produced 0 lines from
> `gcc -m32` beyond those. *The lowering is not silently host-width-dependent* — and that was
> a real question, because Gabbro emits `uint64_t` MMIO accesses and its bank index arithmetic
> is `unsigned int` (which is exactly where §2.2 bites, at **both** widths).

## 2 What was found in the emitted C

### 2.1 A null pointer constant, dereferenced — `clang --analyze`, `core.NullDereference`

The single real analyzer finding in 121 units.

```
static tz : ptr<normal, rw> Platz = 0;      -- 4 items, 0 errors, 0 hints
-> static Platz * const tz __attribute__((unused)) = 0;
-> tz->slots[i].a = 5;
```

The `0` is a **null pointer constant** (C11 6.3.2.3p3); the body below it is undefined
behaviour (6.5.3.2p4). `dokumente/BEWEIS.md` row 9 carried this class as *"Gabbro has no
`null`"* with residual risk **only at the `extern` boundary** — and `beispiele/38` is not at
the `extern` boundary.

**The intent was never wrong.** On bare metal address 0 is a vector slot. The *spelling* was,
and the emitter already held the right one: the MMIO path has written
`(volatile uint8_t *)(uintptr_t)GERAETEBASIS` since it existed, and integer-to-pointer is
implementation-defined (6.3.2.3p5), not undefined. Two spellings for one thing were `W7`;
there is now one. Row 9 is corrected in place, and the probe
(`komplement.rs::ein_zeiger_aus_einer_zahl_traegt_den_uintptr_cast`) falls in both directions.

**This is an emitter repair and not a refusal, deliberately.** Refusing `ptr = 0` would refuse
a legitimate freestanding idiom — the corpus has exactly one instance and it is honest.

### 2.2 `N050` — the bank index multiply is 32-bit, and nothing held it there

`clang-tidy` names every bank accessor
`bugprone-implicit-widening-of-multiplication-result`. Reading one:

```
bank F at 0x0 stride 0x100000 count 0x10000 { reg X : u64 @0x0 class rw }   -- 0 errors
-> return *(volatile uint64_t *)(d->basis + (0) + i * 1048576u + 0u);
```

`i` is a `uint32_t` bounded by `count`; `1048576u` is an `unsigned int`. At `i = 65535` the
product is `0xFFFFF00000`, and the emitted expression yields `0xFFF00000`. **`F[65535].X`
names a register 64 GiB below the one it declares.** Verified numerically in C: `4293918720`
against `68718428160`.

This is the fourth member of the family `N047`–`N049` and the same sentence applies — *a
language whose reason for existing is that MMIO addresses are provably right accepted an
address that is provably wrong* — except that here the address is not misaligned, it is a
**different address**.

`N050` holds `(count − 1) · stride + offset ≤ u32::MAX`, on literals only, the same limit the
three rules beside it set for themselves. Probe: `beispiele/gift/590-bankindex-laeuft-um.gab`.
The boundary is driven from both sides: `0xFFF · 0x100000 = 0xFFF00000` fits and stays silent;
one more cell does not.

> **Whether the refusal or the emitter is the right place is a real question, and `N050` says
> so in its own second note.** A device spanning more than 4 GiB of index arithmetic is a
> legitimate declaration — yesterday's audit measured *an offset beyond 4 GiB* and ruled it
> correct as accepted. What is not legitimate is lowering it into a 32-bit multiply. Until the
> emitter computes bank offsets in `uint64_t`, the checker holds the declaration inside what
> the emitter can represent.

## 3 Half two — the checker, under inputs it did not write

`instrumente/fuzze-grenzen.py`. **15 declaration forms × 60 values = 900 cases**, each run
through **both build profiles**, no external crates, no `unsafe`.

The property is the one this folder lives by — *the checker either accepts, or refuses BY
NAME* — plus the half that makes it mechanically decidable:

> **The two build profiles must agree.** There is no `[profile.release]` in `Cargo.toml`, so
> overflow checks are on in debug and off in release, and **release is what `cargo install`
> produces**. A panic is a third answer; a silent wrap that turns a refusal into `0 errors` is
> a fourth, and it is the worse of the two. *A disagreement between the profiles catches both
> at once and needs no oracle for what the right answer is.*

Values: 41 numeric rungs (`0, 1, 2, 3, 7, 8 … 2^31±1, u32::MAX±1, 2^63, u64::MAX±1, 2^127,
u128::MAX`) and 19 lexical shapes (`0x`, `0b2`, `1__2`, `_1`, `0x` + 33 hex digits, `9`×100,
one past `u128::MAX`).

### 3.1 Three defects, and the first was one day old

| run | panics | debug/release disagree |
|---|---:|---:|
| first | **7** | 0 |
| after the arithmetic repair | 3 | 0 |
| **after the message repair** | **0** | **0** |

**(a) `N049`'s own extent arithmetic panicked in debug and wrapped in release.**

```rust
let bis = von + (*schritt as i128) * (*anzahl as i128);      // namen.rs:1632
```

`*v as i128` on a `u128` is lossy, and the multiplication overflows `i128`. Measured:

```
bank … stride 8 count 170141183460469231731687303715884105727 (2^127−1)
    debug   -> panicked at namen.rs:1632, exit 101
    release -> 3 items, 0 errors, 0 hints, exit 0

bank … stride 8 count 340282366920938463463374607431768211455 (u128::MAX)
    debug   -> 3 items, 0 errors, 0 hints
    release -> 3 items, 0 errors, 0 hints
```

**The second is the worse one and no profile disagreement reveals it**: the cast makes the
product negative, `bis <= von` holds, and the bank goes down the *"`N010` owns the empty
bank"* branch — accepted, in silence, in both builds.

This is the exact shape the other lane found in `@[u128::MAX:0]` on 2026-09-01, **in code
committed on 2026-09-01**. *The audit method that produced `N049` also produced its first
defect, one day later.* The same lossy cast stood in `registerlagen` (`N009`) and in
`ausrichtung_pruefen` (`N047`); all of them now compute in `u128`, saturating.

> `N047` did *not* let `@u128::MAX` through — it fell, because the cast produced `-1` and
> `-1 % 8 ≠ 0`. **A rule that is right because two errors cancel is not a rule that holds**,
> and moving the literal to any aligned value above `2^64` stopped the cancellation. That is
> `N051`.

**(b) `N051` — a layout number wider than the pointer arithmetic it lowers into.**

```
reg X : u64 @0x100000000000000000 class rw     -- 2^68, a multiple of 8
-> 3 items, 0 errors, 0 hints
```

Gabbro's literals are `u128`; the address arithmetic is `uintptr_t`. Above `u64::MAX` there is
no C constant to write and no address to name. Probe:
`beispiele/gift/591-registerlage-jenseits-der-zeigerbreite.gab`. Counter-direction:
`@0xFFFFFFFFFFFFFFF8`, the last 8-aligned offset that fits, stays silent.

**(c) The repair carried the defect it was written beside.** `N050`'s first draft multiplied
in `i128` — the same overflow, in the rule added to catch it. And after the *condition* was
made saturating, three cases still panicked: the `format!` that words the `N048` refusal still
held a bare `von + breite`. **The rule decided correctly and then panicked while saying so.**
*A message is code.*

### 3.2 The instrument was wrong before the tree was — twice

Both were caught by the instrument's own speech test, which is why it has one.

1. **Eight of fifteen templates were not valid Gabbro** (`effects { }` instead of
   `effects { pure }`; a `walk` body with the wrong separator). The sweep measured the same
   parse error 60 times per form and reported **595 "unexpected exits"**. *A generator whose
   baseline does not parse has an empty population, and `W17` says a green judgement over
   nothing looks exactly like a green judgement.* The runner now checks a known-good value per
   form **before** the sweep and refuses to report anything if one fails.
2. **The code extractor stripped `:,.`` ` but not `[]`**, and the diagnostic prints
   `error: [N050] …`. Every correct refusal came back `EXIT1-UNNAMED`.

## 4 The ASan closure, and why it is a location and not a difficulty

`pruefe-emission.sh` stage 6 has run UBSan since 2026-08-19. Stage 6b — ASan — did not exist,
and the comment beside it said why: on the workstation's hardened kernel ASan's shadow map
collides with the memory map and the process aborts before `main`. `TODO.md` carried the line
as open and called it **"ortsgebunden, nicht schwer"**.

`fisch` is stock Ubuntu, and ASan runs there. Stage 6b now compiles every driven unit a
further time under `-fsanitize=address,undefined -fno-sanitize-recover=all`, runs it, and
demands the same result.

**The fallback is in the guard and not in the driver's head**, and it falls on the side of
`W1`: where ASan cannot start, the stage prints `NICHT GEFAHREN` per unit and the closing line
says so. *A skipped probe lowers the number; it does not leave it untouched.* Both branches
are measured: `fisch` → 24 run; workstation → clean ASan program exits non-zero → not run.

> **And the speech test for it was itself the third instrument error of the day.** Its first
> counter-probe was `malloc(4)` with `p[7]`, both constants — `gcc -O1` folds the allocation
> away, ASan sees no heap, and says nothing. So `fisch`, where ASan works perfectly, reported
> *"ASan schweigt"* and the whole stage stayed off. `volatile` on the size and the index heals
> it. **A measuring device whose counter-probe the optimiser removes reports the absence of
> its own subject.**

## 5 What this leaves standing

* **`-O0` vs `-O2` differential**: already stage 5 of the emission guard, over the same 25
  driven units — same result required, and it holds. Extending it beyond those units is not
  possible for want of entry points, not for want of effort.
* **The emitter still does not tell the C compiler that MMIO accesses are aligned.** 100
  `-Wcast-align` sites, now provably aligned by `N047`/`N048`, `N050`. Emitter work, booked
  by the previous audit, still open.
* **`cppcheck` was not run**, and no result should be inferred from that. It is not installed
  and installing it needs `sudo`.
* **Big-endian is unmeasured.** No toolchain, and the one cross compiler present targets a
  sealed architecture.
* **The bank index multiply is refused, not widened.** `N050` is a fence around the lowering's
  current width. Widening it to `uint64_t` would turn the refusal back into an acceptance, and
  that is an emitter decision with a proof obligation behind it.
