## 2 What was found in the emitted C

### 2.1 A null pointer constant, dereferenced — `clang --analyze`, `core.NullDereference`

The single real analyzer finding in 121 units.

```
static tz : ptr<normal, rw> Platz = 0;      -- 4 items, 0 errors, 0 hints
-> static Platz * const tz __attribute__((unused)) = 0;
-> tz->slots[i].a = 5;
```

The `0` is a **null pointer constant** (C11 6.3.2.3p3); the body below it is undefined
behaviour (6.5.3.2p4). `dokumente/BEWEIS.md` row 9 carried this class as *"Gabbro has no
`null`"* with residual risk **only at the `extern` boundary** — and `beispiele/38` is not at
the `extern` boundary.

**The intent was never wrong.** On bare metal address 0 is a vector slot. The *spelling* was,
and the emitter already held the right one: the MMIO path has written
`(volatile uint8_t *)(uintptr_t)GERAETEBASIS` since it existed, and integer-to-pointer is
implementation-defined (6.3.2.3p5), not undefined. Two spellings for one thing were `W7`;
there is now one. Row 9 is corrected in place, and the probe
(`komplement.rs::ein_zeiger_aus_einer_zahl_traegt_den_uintptr_cast`) falls in both directions.

**This is an emitter repair and not a refusal, deliberately.** Refusing `ptr = 0` would refuse
a legitimate freestanding idiom — the corpus has exactly one instance and it is honest.

### 2.2 `N050` — the bank index multiply is 32-bit, and nothing held it there

`clang-tidy` names every bank accessor
`bugprone-implicit-widening-of-multiplication-result`. Reading one:

```
bank F at 0x0 stride 0x100000 count 0x10000 { reg X : u64 @0x0 class rw }   -- 0 errors
-> return *(volatile uint64_t *)(d->basis + (0) + i * 1048576u + 0u);
```

`i` is a `uint32_t` bounded by `count`; `1048576u` is an `unsigned int`. At `i = 65535` the
product is `0xFFFFF00000`, and the emitted expression yields `0xFFF00000`. **`F[65535].X`
names a register 64 GiB below the one it declares.** Verified numerically in C: `4293918720`
against `68718428160`.

This is the fourth member of the family `N047`–`N049` and the same sentence applies — *a
language whose reason for existing is that MMIO addresses are provably right accepted an
address that is provably wrong* — except that here the address is not misaligned, it is a
**different address**.

`N050` holds `(count − 1) · stride + offset ≤ u32::MAX`, on literals only, the same limit the
three rules beside it set for themselves. Probe: `beispiele/gift/599-bankindex-laeuft-um.gab`.
The boundary is driven from both sides: `0xFFF · 0x100000 = 0xFFF00000` fits and stays silent;
one more cell does not.

> **Whether the refusal or the emitter is the right place is a real question, and `N050` says
> so in its own second note.** A device spanning more than 4 GiB of index arithmetic is a
> legitimate declaration — yesterday's audit measured *an offset beyond 4 GiB* and ruled it
> correct as accepted. What is not legitimate is lowering it into a 32-bit multiply. Until the
> emitter computes bank offsets in `uint64_t`, the checker holds the declaration inside what
> the emitter can represent.

## 3 Half two — the checker, under inputs it did not write

`instrumente/fuzze-grenzen.py`. **15 declaration forms × 60 values = 900 cases**, each run
through **both build profiles**, no external crates, no `unsafe`.

The property is the one this folder lives by — *the checker either accepts, or refuses BY
NAME* — plus the half that makes it mechanically decidable:

> **The two build profiles must agree.** There is no `[profile.release]` in `Cargo.toml`, so
> overflow checks are on in debug and off in release, and **release is what `cargo install`
> produces**. A panic is a third answer; a silent wrap that turns a refusal into `0 errors` is
> a fourth, and it is the worse of the two. *A disagreement between the profiles catches both
> at once and needs no oracle for what the right answer is.*

Values: 41 numeric rungs (`0, 1, 2, 3, 7, 8 … 2^31±1, u32::MAX±1, 2^63, u64::MAX±1, 2^127,
u128::MAX`) and 19 lexical shapes (`0x`, `0b2`, `1__2`, `_1`, `0x` + 33 hex digits, `9`×100,
one past `u128::MAX`).

> `N051`.

**(b) `N051` — a layout number wider than the pointer arithmetic it lowers into.**

```
reg X : u64 @0x100000000000000000 class rw     -- 2^68, a multiple of 8
-> 3 items, 0 errors, 0 hints

in `i128` — the same overflow, in the rule added to catch it. And after the *condition* was
made saturating, three cases still panicked: the `format!` that words the `N048` refusal still

*A message is code.*

## 7.2 Coverage, with all three denominators

`fuzze-grenzen.py --deckung` reads the EBNF out of `dokumente/SYNTAX.md` and the numerator out
of the sweep's own form table, so the claim cannot drift from the thing claimed.

| | before | after |
|---|---:|---:|
| EBNF rules defined | 154 | 154 |
| …that **can carry a boundary at all** | 100 | 100 |
| …**driven by the sweep** | **9** | **43** |
| carry no literal — no rung to climb | 54 | 54 |
| forms | 15 | 63 |
| cases (both profiles) | 900 | **5 778** |

**The middle row is the honest denominator, and leaving it out would be `W25` in this tool's
own numbers.** `program = { item }` cannot be pushed to a boundary. A rule counts as
boundary-carrying when *its own production* names a literal slot — `int`, `constexpr`,
`float`, `string`, `ident` or an `expr` — and not when it can reach one transitively, under
which reading `program` carries every boundary in the language, truly and uselessly.

*The count is conservative in the direction that costs us:* where a form drives an inner rule
(`invariant … cost O(N)` is booked to `costexpr`, not to `invariant`) only the inner rule is
counted. **43 is a floor.**

## 7.5 `M139` — a literal so wide that the TYPE falls away, and every rule with it

`m1.rs:1532`, one line, standing since before this audit:

```rust
ExprArt::Zahl(v) => match i128::try_from(*v) {
    Ok(w)  => Typ::Ganzzahl(IntBereich::konstante(w)),
    Err(_) => Typ::Unbekannt,                            // <-- until 2026-09-02
},
```

Literals are `u128`; `IntBereich` is `i128`, because it has to hold a signed and an unsigned
64-bit range in one shape. **`Unbekannt` is not a refusal. It is an acquittal that reads like
caution** — every downstream rule asks for the type first and says nothing when there is none.
Measured on `table T count 8`:

```
T.slots[9]                                          -> M103, the array has 8 elements
T.slots[2^63]                                       -> M103
T.slots[170141183460469231731687303715884105727]    -> M103        (i128::MAX)
T.slots[170141183460469231731687303715884105728]    -> 0 errors    (i128::MAX + 1)
   emitted as:  T_speicher.slots[3402823669…455].a   over  T_slot slots[8];
```

**The index bound holds for every value up to `2^127 − 1` and then stops holding**, and the C
that comes out reads out of bounds — over the one promise this language makes loudest. `M101`,
`M104` and `M117` go quiet in the same step and for the same reason; `const K : u64 = 2^127`
was accepted too.

*The fence, and not the widening* — the fork `N050` already stood at. **The widest integer
type Gabbro HAS is 64 bits**, so a literal above `i128::MAX` is not a value any expression can
take; widening `IntBereich` moves the hole and buys nothing. Probe:
`beispiele/gift/601-an-index-too-wide-to-have-a-type.gab`. Speech test, both directions, with
the two neighbouring values as its first two assertions:
`paesse.rs::ein_literal_breiter_als_i128_faellt`.

## 7.6 The emitter's own `as` cast — the 2026-09-01 defect, one file over

`emit.rs::konst_zahl` read every compile-time number as `Some(*n as i128)`. **This is the same
lossy cast section 3.1 repaired in three places in `namen.rs`, still live in the back end**,
and sixteen sites read through it: bank stride and count, register offsets, array lengths,
`walk` levels and node width, the entry vector, the nesting bound, `const` and `static` values.

It was not found by the property. It was found by reading the C the sweep's accepted rungs
produced:

```
entry e vector 340282366920938463463374607431768211455 arch x86_64 { … }
   ->  3 items, 0 errors, 0 hints
   ->  /* entry e -- arch x86_64
        * vector -1
```

**The emitter did not fail. It wrote a different number** — and the vector is what the
hardware indexes its table with. The other end of the cast reached the diagnostics:
`static mut A : [u64; u128::MAX]` was refused as an *"array of length zero — C has no such
object"*, **a message that is wrong about the very number it is quoting.** *A rule that is
right because two errors cancel is not a rule that holds*, written on 2026-09-01 about `N047`
and true here at the same hour.

`konst_zahl` now answers `i128::try_from(*n).ok()`. All sixteen callers already had the

cannot represent belongs. Probe:
`beispiele/gift/602-an-array-length-the-emitter-read-as-minus-one.gab` (`C001`, so the gift
harness runs the emitter over it). Speech test:
`rechenwerk.rs::der_erzeuger_liest_kein_literal_falsch`, whose claim is carried by what must
**not** appear — a `-1` near the vector, the words "length zero" about `2^128 − 1` — with
`i128::MAX` and `0x80` as the counter-direction.

   `ensures`, and in a table `invariant`. That is not a boundary defect — it is pass coverage
   over predicates, a different lane and a different denominator (`messung/PASSREGISTER.md`).
   *It is the larger of the two findings in this section and it is not mine to close in
   passing.*
2. **`aligned(p, 0)` and `aligned(p, 3)` are accepted.** An alignment of zero lowers to a
   modulo by zero; a non-power-of-two alignment is not an alignment. Both are refused at
   `emit` today, but by `C001` *"`aligned` outside a `format` predicate"* — the right answer
   for the wrong reason, and it disappears the day `aligned` lowers there.
3. **`entry … vector <u128 literal>` still emits**, now saying *"vector: not a constant in
   this unit"*. It **is** a constant; it is one the emitter cannot write. The honest answer is
   a named refusal at check time, in the `N051` family.
4. **`table count 0`, `[u64; 0]`, `embeds … scale 0`** are accepted by the checker. The first
   two are refused at `emit`; `scale 0` lowers, and multiplying an extracted frame number by
   zero yields address zero for every input.
5. **A 65 536-character identifier is accepted** and written into C, where C99 5.2.4.1
   promises 63 significant characters in an internal name and 31 in an external one.

## 7.8 What was not swept, and why

* **57 of the 100 boundary-carrying rules.** The bulk are statement and predicate forms whose
  only literal slot is an `ident` (`leavestmt`, `nextstmt`, `breakstmt`, `observestmt`,
  `kante`, `regbind`, `right`, `space`, `opname`, …). Each needs a valid enclosing program of
  its own, and the identifier ladder over six positions already exercises the lexer's answer
  for all of them. *That is a reason, not a proof — the six positions are not the sixty.*
* **`asmrumpf`, `asmop`, `check`, `entrustdecl`, `state`, `transition`, `variants`,
  `matchstmt`, `exchstmt`, `awaitload`** — reachable, and each wants a hand-built baseline.
  The generator refuses to report anything when a baseline fails (§3.2), so a rushed template
  costs a run and not a false finding; they are absent because they are unwritten.
* **Combinations.** Every form moves ONE slot so that a finding names one field. `stride` and
  `count` at their boundaries *together* is a different sweep, and `N049`/`N050` live exactly
  there.
* **`gabbro emit` is not part of the property.** §7.6 was found by reading generated C by
  hand. A sweep that ran the emitter over every accepted rung and held it to *"lowers, or
  refuses by name"* is the obvious next instrument, and it does not exist.
