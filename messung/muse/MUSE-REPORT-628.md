### Theorems

- `intWort_zahlWort`: on a `repOk`-admitted range the 599 modular word
  is the 570 representation word (both bounds used).
- `senkAssign_ok`: shape (successful fragment lowering extends with the
  store).
- `evalTrans`, `paarCancel`: transport helpers with fully variable
  type sides (`cases` applies); instantiated with the stuck field-type
  equation at use sites.
- `senkAssign_korrekt` (main): admitted `assignSlot` with a 599-fragment
  value agrees between source `execStmt` and target `lauf` over the
  generated `prog ++ [store64]` (encoded lengths), concluding register
  value (`intWort` of the actual evaluation), `s.speicher = m'`,
  `RepSlot` and `wortZahl` read-back. The statement carries the
  transported expression `cast (congrArg … hT.symm) e` at the field
  type; the fragment lowering runs on the constructor-headed `e`, so the
  sequence is generated from the admitted statement, not chosen. Value
  flow is derived (`senkung_korrekt` + `heval` naming + bridge), never
  an assumed eval/target equality.
- Planted refusals: `senkAssign_verweigert_mul`,
  `senkAssign_verweigert_tief` (unsupported expression/nesting),
  `assignRepOk_negativ_verweigert` (negative range),
  `assignCodeAlias_verweigert` (code extent overlapping the slot extent),
  `witByteFaelschung628` (forged executed opcode byte admits no
  fetched transition), `witRegionGetrennt628` (witness code/data
  separation, positive).
- `witSenk628`, `witSenkAssign628`, `witUmgebung628`, `witFrisch628`,
  `witHRsp628`, `witHBasis628`, `witHBaseR628`, `witHa628`,
  `witHTgt628`, `witHRd628`, `witOk628`, `witHk628`, `witHeval628`,
  `witHT628`, `witHw628`, `witHL628` (witness-side premise facts).
- Fetched-byte witnesses by `decide`: `witBytesWert628` (`rax = 42`
  after 4 fetched steps), `witBytesSpeicher628` (data cell `0 -> 42`),
  `witLaufAendert628` (memory-changing run).
- `senkAssign_korrekt_zeuge`: JOINT witness instantiating every premise
  of the main theorem on the non-degenerate package (table its function
  writes; source slot `12 -> 42`; target bytes change; fetched run
  changes memory) plus all conclusions.

## Notes on the task

- The awaited "exact accepted599 interface" was present in-tree
  (`ExpressionLowering.lean` merged with review 611); no blocking
  dependency remained.
- One real subtlety, not a task defect: the statement's value
  expression must be constructor-headed at `.int lo hi` for `senkFrag`
  while the `Stmt` needs it at `D.typ t f`; this is handled by an
  explicit `cast (congrArg … hT.symm)` in the statement plus the two
  transport lemmas, with the witness (`hT = rfl`) reducing
  definitionally. The generated sequence still comes from the admitted
  statement's own syntax.
- `heval : (eval σL e σL ρ).n = v.n` names the evaluated source value
  (the same role as `hk`/`hv` in accepted 570); the register/memory
  correspondence itself is derived through `senkung_korrekt` and the
  bridge, not assumed. If the reviewer wants `hv`-form instead, it is
  derivable in three lines from `heval` via `evalTrans`/`paarCancel`.
