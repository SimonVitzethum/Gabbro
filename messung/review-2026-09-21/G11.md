## 4. Open findings, by severity

**F1 (high, Lean branch only): the (d2) premise is vacuous, and the model has no child
thread.**
- `Laufzeit.start` puts every initial thread at `none` (the root) or at `some a.1` with
  `a ∈ E.starts`.
- `Laufzeit.klon` = `CloneStart … (E.ws.map some)` forbids a gate entry from being a declared
  start, and `E.ws = E.starts.map (·.1)` (Spec.lean:429).
- So under (d) no initial thread sits at a gate entry.
- `CloneHandoff` only quantifies over threads whose START head `(M0.faeden t).kopf.f` is a
  gate entry, and `RufStartG` sets that head to `(init t).1`. So `CloneHandoff` holds
  vacuously for every reached `M`, and **(d2) follows from (d)**.

Consequences:
- nothing is weakened;
- the "model side of the checked handoff" (SATZKARTE §39) models no child at all;
- `cloneHandoff_start` (reflexive run, log = the entry event only) is the only run-level
  witness, so there is no non-degenerate witness of a gated run;
- review question 2's "nothing else restricts the quantified runs" is kept only because (d2)
  is empty.

Before that branch is taken in, (d2) needs a child population that can actually occur (a
spawn rule in machine G, or a start class that admits entries), and a witness with a
non-empty `klon` and a run of length > 0.

**F2 (high, latent while C185/LG004 stand): the child is not a thread for race or lock
analysis.**
- `fusswache2.rs::begehe` (line 498) walks `child` with the ENCLOSING held set. A `child`
  inside `locks L { … }` is analysed as holding `L`, but the parent holds `L`, not the child.
- The signature-held locks of the enclosing function are carried in the same way.
- Nothing refuses `child` inside `locks`/`observes`.
- Reads and writes of globals and tables on the child path are "legal" (`clone.rs:404`), and
  no pass treats the child as a concurrent thread beside the parent. `H013`, `Getrennt` and
  the start fan-out all quantify over declared starts only.

Scenario: `locks L { g = 1; child { g = 2; ausgang(0); } }` is checker-clean today. Once lowered,
the child writes an `L`-guarded carrier without `L` while the parent keeps writing it — a race.

Must be closed before lane 258 lifts `C185`: refuse `child` under `locks`/`observes`/held
signatures, and model the child as a start for race freedom.

**F3 (medium, latent): the spill-read set is `emit::benutzte_namen`, an emission-oriented
walker.**
- It skips `Grow(_)` entirely (emit.rs:8771). A caller `let` read in a `grow … else { … }`
  on the child path escapes N451/N452.
- It reads only the body of `locks` (8625), not the lock place's index expressions.
- `Alt`, `Eingebaut` and `Ergebnis` are skipped. That is harmless because they are not
  run-time reads.

Scenario: `child { grow A by 1 else { ausgang(v); } … }` with `v` a caller `let`: no N451.
Today `grow` is refused at emit.

**F4 (medium, latent, design): which region belongs to which gate call is unit-wide.**
- `N450` counts stack gates across the whole unit (clone.rs:263). A `child` block in a function
  that never calls a gate, or one whose prefix holds no gate call, passes N450. With an empty
  handed set it passes N451/N452 as well, if it reads no caller name.
- The "inline trap, child entered by jump" lowering has no well-defined target there, and none
  either when there are two regions after one call.
- The code between the gate return and the region (`if v == 0` in example 155) runs on the
  child's stack under a fork-style reading. It is sound only under the jump reading, which
  nothing states or checks.

Lane 258 needs a per-call-site association rule.

**F5 (low): doc and sentence remnants.**
- The `saetze.rs` sentence text still says `KlonAnnahme` (saetze.rs:4012). It was left alone to
  keep the sentence guardian's input stable.
- The gift headers 1113 and 1115–1117 say "without this rule NOTHING falls". At the checker
  that is true, but `C185` falls in every one of them.

**F6 (low, pre-existing, same class): other hand-listed walkers are blind to `child` (and
often to `observes`/`alloc`/`grow`).**
- `kosten.rs` `schleifenzusagen`/`sperrbloecke` also miss `Observiert`, `Alloc`, `Grow` and
  `Exchange`.
- `gegenbeispiel.rs` (`stmt`, `rufe_in_block`, `rufe_bedingt`, `sperr_abschnitte`) and
  `obligations_g.rs` (the same three) are reporting and G-export tools; `child` is refused
  there by LG004.
- `zeremonie.rs::anweisung` is only a count.
- `m1.rs::endet_immer` answers `false` for a trailing `child`, which is the safe direction.
