## Findings, ranked

**F1 (medium, FIXED `af9774da` [UNBUILT]) — the joint witness's divergence leg was vacuous.**
`foreverLauf … 0 σ ρ = .hardware (.fortschritt a)` is the first defining equation
(`Semantik.lean:576`), for every loop — false guard, leavable body, anything. The witness stated
the divergence at `execStmt divO 0 …`, so that conjunct held by `rfl` independent of the
`hNo`/`hInv` it existentially binds: the "same exit evidence proves the divergence" sentence was
true of the proof term but not load-bearing. The report's planted defects (false invariant,
leavable body "fail red") could not have failed at budget 0; they must have used a general
budget (not re-run, not measured). At budget 3 a false guard yields `logik .schleife` and a
`leave` yields `ok`, so the conjunct now depends on the evidence.

**F2 (medium, OPEN, model/C) — the model's never-asm reading is exactly what the emitted C did
not deliver.** `asm_never_kein_ok` (`Divergenz.lean:169`) and `asm_never_antwort_leer` (`:159`)
rest on `execBlock_bindAxiom_never` (`NeverAsm.lean:72`): a `-> never` axiom has an empty answer
class, so a return is filed as `hardware (annahme a)` / progress stop `nieZurueck`. That is sound
*as a named assumption*, but it is the assumption "the asm never returns", and G04 F1 showed the
lowering of `asm { "hlt" }` into a `_Noreturn` function lets control fall off the end after an
interrupt (C11 UB). G04's fix `cacb80ba` `[UNBUILT]` addresses the C side; until it is built and
merged, the Lean lemmas describe a program the C does not implement. The model is not wrong, but
lane 231's header (§2 "the call never continues") should be read as "by assumption", not as a
property of the emitted code. Nothing in Lean ties the axiom to its C lowering.

**F3 (low-medium, OPEN) — the `KeinLogikHaltG` "bridge" is narrower than claimed.**
`ewig_wahr_schreitet` (`:196`) covers only the head `.ewig a (n+1) .wahr .nil k` — the empty
spin with guard `true` — not "a true-invariant `forever`". It is a stepping (progress) lemma,
not a `KeinLogikHaltG` statement, and it has **no witness** reaching such a G head (the witness
run is on the F machine and stands at `.cons divSchleife …`, not at a G `.ewig` residue), although
its premise `hhead` is a ∀-over-machine-syntax equation (zeugenpflicht). `nieZurueck_blatt_frei`
(`:220`) is vacuous by constructor discrimination (a `bindAxiom` head is never a leaf head); it
proves nothing about never-axioms specifically. Neither weakens the goal (`Spec.lean` untouched,
the file's own CUTS says "per-head, not the leg"), but "divergence serves `KeinLogikHaltG`"
overstates both. Suggested: a G-machine witness for `ewig_wahr_schreitet`, or rename the section
"one-step facts".

**F4 (low, OPEN) — `asm_never_kein_ok` duplicates `NeverAsm.lean`.** It is `execBlock_bindAxiom_never`
plus `cases`; `NeverAsm.lean` already has the sibling `bindAxiom_never_kein_logik`. Harmless.

**F5 (medium, OPEN, model vs Rust) — the fd fixture does not model lane 226's gates, and
`AxVertragO` has no argument precondition.** Example 150 has `opaque type Fd = u32`,
`gate_read(fd, buf : ptr<normal, w> u8, len)` and "writes buf"; the Lean fixture has the fd as a
plain `.int 0 7`, no buffer or length, and a read oracle that writes no memory
(`FremdRuf.lean:166`). More importantly, `AxVertragO` (`AxiomVertrag.lean:50`) quantifies over
**every** argument environment: the ensures must hold whatever the caller passes. A real `open`
depends on a NUL-terminated path (G04 F2: example 149 passes a `pathlen`-bounded, not
NUL-terminated path, and the emitted C calls Linux `open`). In the model, the kernel's resulting
`-EFAULT`/garbage return either fits the declared range and must meet the ensures (false for a
real kernel — the hardware premise is then simply untrue) or does not fit and becomes
`hardware (annahme a)`. Either way a *caller* bug is booked as a hardware-assumption failure, not
as user logic. The model has no place for gate requires. Also `fdQ` for open promises a nonzero
descriptor (`:157`), while fd 0 is a valid Linux descriptor — fine for a fixture, but not an OS
fact. Recorded in the CUTS block by `639e09fa`; the modelling gap itself stays open.

**F6 (low, FIXED in docs `639e09fa`) — `fd_opak` is a fact about `fdO`, not opacity.**
`fd_opak` (`:402`) is `rfl` on the witness oracle, which ignores its argument by construction.
It says nothing about the language (the descriptor is an `.int` expressions can compute on) and
the opposite of a real kernel (whose read answer depends on the fd). The header ("the descriptor
is never computed on") and the report ("opacity", "exactly the lane-226 shape") were narrowed.

**F7 (low, OPEN) — the gate theorems are unfoldings of their premises.**
`fremdruf_gate_gilt` is `hQ … hfit` plus `(hO …).1` rewritten by `hEff`; `fremdruf_offen_lesen`
is two applications. `GateData.num/regs/kosten` are never constrained, which is stated honestly
in CUTS. The witnesses are non-degenerate (real fits `3` and `0`, a reached write `0 -> 5`), but
the reached run fires a plain leaf, not a gate call (stated in CUTS). No overclaim beyond F5/F6.
