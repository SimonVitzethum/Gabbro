## Focus questions

**Do E010/E011 catch every traverse object read?** For the object expression itself, yes:
`liest_expr` covers places with nested fields and indices (`c.slots[i].x` renders as one place
and reads `i`), call arguments, library-call arguments, `count`, `aligned`, and `lenof` indices.
The `_ => {}` arm in `liest_expr` only catches literals, `FnWert`, `Alt`, `Ergebnis`, `Grund`
and `ArrayLit` (which is const-initialiser only, per `ast.rs`). Calls in the object are seen by
the function-level call walk (`eigene_ausdruecke` includes `t.gegenstand`). Gaps:

- **Calls in the traverse body (or in the object) are never held against `touches`** — F2.
- **Parameters are filtered out** (`bekannt` only keeps world names), so a traverse over a
  pointer parameter checks nothing against `touches`. This was already booked
  ("a `traverse` over a PARAMETER is not held against it").
- `let … else` source and `retry … until` remain unwalked (booked before this lane).
- **Early exits** do not matter here: `E010`/`E011` are flow-insensitive and collect reads on
  every path, reachable or not.
- Nested traverse: the inner walk's carrier (`domaene_liest`) *is* held against the outer
  `touches`, although the lane pins that the carrier stays out of `touches` at the top level.
  Over-strict at worst, never unsound; not changed.

**Is N421 a real refusal?** Yes: `Absage::fehler("N421", …)`, sentence `kosten.haltezeit_fenster`
in the same commit, poison `beispiele/gift/1082` (`-- erwartet: N421 allein`), positive probe

## Open findings, by severity

**F3 (high, pre-existing, G07's root cause as it reaches K002/K001) — integer `match` counted
as total in the cost summation.** `lib.rs:1443` `endet_immer` says a `match` ends when every
arm ends; no checker pass requires an integer `match` to be exhaustive (only `emit.rs` touches
`intpat`, and `match_int` emits a `switch` **without `default`**, emit.rs:12458). `kosten.rs`
`block`/`rest` (≈ lines 838–880) use `endet_immer` to take `max(durch, vorbei)` instead of a
sum. Scenario, inside a lock or a traverse body:

```gabbro
locks L {
    if c { match heavy() { 0 => { return; } } }
    long_tail();
}
```

When `heavy()` returns 1 the switch falls through and the real path is
`c + heavy + long_tail`; the pass counts `max(c + heavy, c + long_tail)`. `K002` (hold time)
and `K001` can accept a block that overruns its promise by `min(heavy, long_tail)`, multiplied
by the domain bound inside a traverse. Fix belongs with G07 (an exhaustiveness refusal for
integer `match`, or `endet_immer` answering `false` for any `match` with `intpat` arms). Not
fixed here: it changes verdicts corpus-wide and needs a build.

**F2 (medium, pre-existing, now booked) — `E011` holds direct deeds only.**
`wirkungen.rs:534` `pruefe_touches` walks `sammle_taten`, which records call ARGUMENTS but not
the callee's effects. `traverse i over slots of w touches reads w.slots { schreibe_global(); }`
passes E011 while the loop writes a global. The function-level call check still holds the
callee against the function `effects`, so this is not a hole in `effects`; it is a hole in the
narrower `touches` promise, which the costs and lock arguments are said to rest on. The sentence
claimed "touches no more than `touches` names"; the vorbehalt now says calls are exempt
(`55ee8760`). Real repair: map callee effects into the traverse walk (same machinery as
`aufrufwirkungen`).
