## Findings, ranked

**F1 (high, FIXED in `cacb80ba`): the never-asm C was undefined behaviour, and the lane's
proof was blind to it.** `emit.rs:7621–7666` (master) lowered
`divergent fn halt() -> never … = asm { "hlt" }` to
`_Noreturn void halt(void) { __asm__ __volatile__("hlt\n" : : : "memory"); }`. The asm text
is unchecked, and `hlt` **resumes after the next interrupt**. Control then falls off a
`_Noreturn` function, which is undefined behaviour (C11 6.7.4p8). Measured on that exact shape:
`gcc -std=c11 -Wall -Wextra -Werror -c -O0` refuses (*'noreturn' function does return*), and
`clang … -fsyntax-only` refuses (`-Winvalid-noreturn`). `gcc -fsyntax-only` and `gcc -O2`
pass. `never_lowering.rs::cc_nimmt_an` used `gcc`-style `-fsyntax-only`, where GCC does not
run that middle-end warning, so the lane's claim "*A `_Noreturn` body that returned … would
fail here*" was false for gcc. Failure scenario: a kernel idle routine written as the flagship
shape wakes on a timer interrupt and runs into whatever code follows. The model has no such
path: `NeverAsm.lean` reads a returning `never` axiom as a stop that never continues. The fix
makes the C say the same thing in well-defined form. I chose a spin over `__builtin_unreachable()`,
which would hand the UB to the compiler for exactly the case that really happens. The fixed
shape was measured clean under gcc and clang at `-fsyntax-only`, `-O0 -c` and `-O2 -c`.

**F2 (high, OPEN): example 149's `open` gate is not Linux `open`, and the emitted C calls it.**
`beispiele/149-fd-offen.gab:56–58` declares `abi linux arch x86_64 number 2` with
`regs in { rdi = path, rsi = pathlen, rdx = flags, r10 = mode }`. The file says the number "names
this gate's slot in the program's own dispatch, not a kernel table" (line 78), but under
`abi linux` the emitter loads it into `rax` and executes `syscall` (`emit.rs` ~8354/8393). That
is `sys_open(const char *path, int flags, mode_t mode)`: `pathlen` arrives as `flags` and
`flags` as `mode`. Worse, the kernel reads `path` **up to a NUL**, not up to `pathlen`. A
Gabbro path carries no terminator (the file cites the N052 lesson itself), so the kernel reads
past the declared `reads path` frame. That is an out-of-bounds read that `GutO` (the named
frame assumption) calls impossible, and the reason is the user-made declaration, not the
hardware. This is the class `gift/661` refuses for `extern fn open`, re-entered through a
`syscall` item. **Not fixed:** a correct Linux `open` needs a NUL-terminated path, which the
language cannot state today. Options: withdraw 149 from the emitting corpus, or move it to an
invented `abi` and make it a checker-only example. Emission of 149 is booked in `MARKE_EMIT`
(123). Whether `pruefe-emission.sh` ever *executes* `gate_open` was not measured.

**F3 (medium, OPEN): the read gate's frame is not tied to `len`.**
`beispiele/150-fd-lesen.gab:46–61`: `gate_read(fd, buf : ptr<normal, w> u8, len)` has
`requires len <= MAXLEN` (1024) and `effects { writes buf }`, and `lies` forwards any
`len <= 1024` with any `ptr u8`. `zaehle` happens to pass a 64-byte `EIMER` with `CAP = 64`
(line 100), which is safe. But `lies(fd, EIMER, 1024)` would check clean (not measured, by
reading), and the kernel then writes 1024 bytes into a 64-byte static. The declaration promises
a frame the real kernel exceeds, and nothing links a pointer's extent to a length at a user-made
gate. Per `Spec.lean` §(c), a false `GutO` frame is a false *hardware* assumption, but here it
is false by the user's own declaration. This is the "user-made gates" design showing its trust
boundary. The example presents the shape as safe.

**F4 (medium, OPEN): open/read hang on the *write* assumption and its write-only probe.**
149, 150, 1067 and 1068 reuse `linux_write_contract` ("Write keeps its contract on this
machine.") with falsifier `sonde_write`. `sonden/sonde_write.c` says it "belongs to EXACTLY
this one obligation (N024)", and it tests only `write` into a pipe. So open's
`ensures result <= 4294967295`, read's `ensures result <= len` and the ENOENT/EACCES/EEXIST and
EINTR/EINVAL maps rest on a named assumption whose name and probe cover none of them. The lane
says it did this to stay out of the `N024` probe quota ("no new row"). That is the probe
obligation sidestepped by reuse, not met. It matters because an out-of-range answer at the
syscall value leg is lowered to `__builtin_unreachable()` under that assumption
(`emit.rs` ~8385–8401).

**F5 (low, OPEN): gift 1068's "honest twin" forges a descriptor.**
`beispiele/gift/1068-fd-wird-gerechnet.gab:9,33–37`: `scheck` returns the flag word
`kennzeichen : u32` as an `Fd`, and the comment calls this the green alternative. Inside the
module the `u32 → Fd` conversion is silent by design (`D004` stands at the wall), so the probe
correctly shows that the carrier protects only *across* modules. The prose presents that as the
way to do it. A `return fd;` twin would say what is meant. I did not edit it: this is a
probe file, and a change there needs the corpus run.

**F6 (low, OPEN): `costs` on `-> never` means three different things.** A total `costs` over
a `forever` never-body is refused (`K003`, gift 1062). An `asm` never-body *must* carry one
(`A003`, gift 1065). A never-body ending in a tail call may carry one (225 test (d),
`costs <= 8 ops`). None of these breaks a guarantee: `ZeitAb` is the syntax bound, and declared
`costs` are not in `Deklaration` (`Spec.lean` ~382). But no sentence says what a `costs` bound
on a function that never returns promises. Separately, gift 1058's comment points to
`MUSE-REPORT-223.md` as where "the named assumption" lives. The register entry is the
`kosten.summation` sentence in `saetze.rs`, not the report.

## The focus questions, answered

- **Did lifting the refusal open an unsound acceptance?** In the checker, no: 225 changed no
  rule, and the `forever` half rests on existing `S009`/`S006`/`K003`, pinned both ways. A
  never-asm body *can* return (`hlt`), and that is trust like any foreign body's `effects`. The
  model covers it as a stop with no logic outcome, consistent with `KeinLogikHaltG` and with
  `FortschrittG` naming `nieZurueck` (`NeverAsm.lean`). The unsound part was the **C**
  (F1, fixed). The sentence now names the trust explicitly.
- **Is the fd carrier race-free and are its gates sound?** The carrier is a plain value
  (`opaque type Fd = u32`): there is no shared state, so there is nothing to race on. `EIMER`
  falls under the existing static-mut discipline, which was not re-checked here. The gates are
  **not sound** as demonstrations (F2, F3, F4).
- **Is the extern-cost edge pinned or silently trusted?** It is trusted, and the trust is
  named (`kosten.summation` vorbehalt) and pinned in both directions (1057 `K003 allein`,
  1058 `K001`, `trusted_extern_costs_count_at_callers`). By reading `kosten.rs:494–516`, the
  call edge reads only the *declared* costs, so a bodied callee without `costs` is also unknown,
  and `K003` propagates transitively. It is not in `Spec.lean`'s assumption list, which is
  consistent because declared costs are not in the goal theorem.
- **Does 235's lowering match the accepted semantics?** It did not for a returning asm text.
  It does after `cacb80ba` (not built).
