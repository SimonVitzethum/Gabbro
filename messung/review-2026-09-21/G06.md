`Akzeptiert` (Akzeptiert.lean:312, :331) are unchanged. So `gabbro_ziel` and its
premises are not weakened. Nothing in `Ziel` uses the new definitions.

**(2) Does narrowing N304 trade a guarantee?** This is the finding with the highest
stakes, F1. Reasoned informally, the newly accepted pairs look race-free: every carrier
the routine's graph writes is lock-guarded, atomic or per-core. Writes and bare reads
of a guarded carrier need the lock (H007, per the lane's demo). Different-start pairs
are still judged by N300/N301. **But no proved theorem covers them.**
`RennfreiBis` over multiset starts is explicitly NOT proved (PoolSym.lean CUTS). The
Lean goal Bool still refuses every duplicate. So the Rust checker is now *wider* than
`Akzeptiert`. The model has only a separation lemma (`pool_schreibt_nicht(_lauf)`)
and a lock-exclusivity bridge.

**Gift numbers.** 1097/1098 are outside the AGENTS.md §7 block (1052–1086). They are
inside the block TODO.md assigns to lane 245 (`N436–440 / 1097–1101`, TODO.md:201),
so there is no violation. AGENTS.md §7 is stale on this point. No collision:
`find beispiele -name '1097*' -o -name '1098*'` yields only the two gift files.

narrowing.

**(3) Are the witnesses non-degenerate?** Only in part, F4.

**(4) Ticket lock.** See §4. No fairness or starvation-freedom claim is made. The

## 3. Findings, ranked

### F1 (HIGH): the Rust checker accepts duplicated starts that no theorem covers and that `Akzeptiert` refuses

`crates/gabbro-check/src/fusswache2.rs:1271-1280` fires N304 only when
`!pool_sicher`. N315 (:1315) fires only when `idle`. Suppose a routine is busy
(it writes, or it has a footprint) and pool-safe. Then **neither fires**. The test
`pool_sauberer_arbeiter_bleibt_still` pins this, and so does
`pool_reine_leser_bleiben_still`: a pure reader has a footprint, so it is not idle.
- Lean side: `Akzeptiert` still demands `einzelnB ws` (`ws.Nodup`). `gabbro_ziel`
  therefore says nothing about these programs. PoolSym's run leg excludes unguarded
  writes per thread and never assembles `RennfreiBis`, `KeinWarteZyklus` or the other
  `Ziel` legs for duplicated starts.
- **Concrete scenario:** `concurrent { arbeiter, arbeiter }` with `arbeiter` doing
  `locks L { setze(30); }` passes `gabbro pruefe` with 0 errors. No proved statement
  of the repo covers its race freedom, deadlock freedom or lock invariants. Before
  lane 245 the same program drew N304.
- It is recorded, and not hidden: TODO.md:495-500 (P0 "Symmetric starts in the
  model") and MUSE-REPORT-245 §3.2–3.3. OFFEN O17 covers only the per-core part.
  Measured against AGENTS.md §1 end sequence (model first, then transfer into the
  checker), the checker has moved ahead of the model.
- Oddity: an IDLE duplicate (strictly harmless) is still refused (N315), while a busy
  pool-safe one passes.
- **Recommendation:** either perform the `einzeln` → `EinzelnPool` swap with the
  `RennfreiBis`/`laufzeit_voll` legs proved (wave B), or gate `pool_sicher` until then.
  Not reverted here: that is a policy decision against Simon's threading MUST.

### F2 (MEDIUM, fixed in `b76ecdac` [UNBUILT]): the `rennboden` sentence contradicted the checker

`saetze.rs` `wirkungen.rennboden` claimed that a routine is admitted "never twice
under one name, idle or not (`N315`, `einzelnB`: `ws.Nodup`)". After a5a5be9e that is
false for busy pool-safe routines. The sentence now states the divergence and names
the open swap.

### F3 (MEDIUM): MUSE-REPORT-245 §3.3 rests on a premise the code does not bear out

The report says the lane-208 diff probe cannot see the divergence, "because `lean_g`
refuses multiple starts (LG004), so pool units never enter it". TODO.md:337 says the
same. But `crates/gabbro-check/src/lean_g.rs` `check_starts` (:3202-3234, and
identically at base `f6eeef72` :3089) has **no** refusal for more than one start or for
a repeated start. Every `concurrent` member is pushed into `starts`. A lock-free pool
unit that is otherwise in the fragment would therefore export (static reading, not
run), for example `pool_reine_leser_bleiben_still`'s `concurrent { leser, leser }`.
Lean `einzelnB` would then refuse it: a visible Rust-accepts/Lean-refuses
disagreement. It is sound in the Lean direction, but it contradicts the report's "not
a bug" reasoning. Since lane 255 (exporter now carries locks, held sections and
multi-starts), guarded pools may export too. **Needs measurement on fisch.** The lane
report was not edited, because it is an audit record.

### F4 (MEDIUM): the pool witnesses are weak, and the main legs have none

- `pool_schreibt_nicht_zeuge` (PoolSym.lean) instantiates the premises jointly, so
  they are not vacuous. It is degenerate in two ways. (a) `fs = []`, so `reachB` never
  unfolds anything; the graph premise is discharged by `reachB_wurzel`. The iff lemmas
  need `hvoll : ∀ g, g ∈ fs`, and the witness's `fs` violates that. (b) The carrier
  `frei` is written by *no* function. So the conclusion
  `TraegerSchreibt g frei = false` holds whether or not `hpool` holds, and the witness
  never exercises the lemma's content. `poolP`'s bodies are trivial `ret`.
- A non-degenerate witness would carry an unguarded carrier that some function
  outside `w`'s graph writes, with a complete `fs`.
- `pool_schreibt_nicht_lauf`, `einzelnPoolB_iff`, `poolSicherWB_iff`,
  `einzelnPool_paar` and `akzeptiertSpec_pool` have no `_zeuge`. CUTS admits this for
  the run lemma ("no finite fixture supplies a `LaufG` run"). By the
  `zeugenpflicht` memory, the ∀-over-syntax iff lemmas owe one on a fixture with a
  complete member list.
- `poolSicher_refD_unmoeglich` (the refusal direction) is fine.
- Also inaccurate: the PoolSym header says the checker admits a pool "IFF the routine
  is pool-safe ... guarded by a lock or atomic". The checker also admits per-core
  writes, which the model does not cover (O17).

### F5 (MEDIUM, merge interaction 245 × 246; comments fixed in `dd23df3a` [UNBUILT], code NOT fixed)

`crates/gabbro-cli/src/bau.rs` `treiberregel` deduplicates `concurrent` names: "Union,
not refusal ... one root and one thread". It was written against a checker that
refused every duplicate: its doc table said N304 refuses `concurrent { f, f }`. Lane
246 (`53dfcf63`) was based on `f6eeef72`, before lane 245 merged.
- **Now:** for an accepted pool `concurrent { arbeiter, arbeiter }`, `gabbro build`
  generates a driver that starts **one** thread.
- The pin (`treiber::pin_pruefe`) compares **sets**, so it passes. The result is a
  silent under-start. The runtime then deviates from the declared starts, which is
  assumption (d). This is not a safety loss (fewer threads), but it runs something
  other than what was declared and measured.
- Fix path: one wrapper per name, one `pthread_create` per occurrence, and a multiset
  pin with an `N_WURZELN` count over occurrences. Or refuse duplicates at the build
  and route pools to `start_pool.c`. This is not obviously small, so it was left as a
  finding. The comments now state the gap.

### F6 (LOW): `laufzeit/start_pool.c`

- pthread use is correct: array sized by `POOL_N`, join loop over all threads, no
  argument, mutex primitives abort on error, `POOL_N < 1` refused at preprocessing.
- If `pthread_create` fails at thread k>0, `main` returns 2 while threads 0..k-1 are
  still running (no join). The process exits, so this is harmless on hosted, but the
  comment claims "join covers exactly the spawned set".
- `POOL_PRUEFE` is called after the joins without taking the lock. The lane's demo
  `pruefe` is declared `requires Held(L)`, so the driver violates the callee's
  contract. It is single-threaded at that point, so there is no race, but it is a
  contract breach in the driver.
- The driver supports exactly one lock (`POOL_SPERRE` is mandatory). A lock-free
  (atomic-only or read-only) pool must still name a lock and gets unused symbols.
  Several locks give link errors, which is loud and fine.
- MUSE-REPORT-245 §1 F3 claims that "N is a runtime choice; the checker admits the
  shape for any N by the same argument", with runs at N=4/8 for a source declaring
  two starts. That is an over-claim: assumption (d) is the declared start list, and
  8 threads for `[arbeiter, arbeiter]` is outside it.

## 4. Lane 247 (report only, `0bd0d6f2`)

The diff is only `MUSE-REPORT-247.md`. `laufzeit/sperre.gab` was unchanged by the
lane. Checked against `sperre.gab`:
- **Orderings:** draw relaxed (CAS on `NEXT`), spin acquire on `NOW`, `gib` does
  acquire-load + release-store on `NOW`. Mutual exclusion holds. Ticket uniqueness
  comes from the RMW total order on `NEXT`, and the release/acquire pair on `NOW`
  publishes the critical section. The acquire on `gib`'s load is stronger than needed
  and harmless.
- **Overflow:** both counters are `u32` and wrap through `folge` (`+%`). This is
  correct while fewer than 2^32 tickets are outstanding, as the file header and the
  `CTicket.lean` CUTS state.
- **Fairness:** no starvation-freedom or FIFO claim is made anywhere, consistent with
  NOT CLAIMED. The report documents the reverse honestly: the `bounded 64 ops` draw
  loop fail-stops under contention (F-247-2). The 1 431 655 765-pass spin bound can
  also fire when a hosted holder is descheduled for long.
- The scratch driver in the report does not check `pthread_create` return codes. It
  is scratch and not committed.
