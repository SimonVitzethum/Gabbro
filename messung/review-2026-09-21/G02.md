## Open findings, by severity

### F1 (medium-high): same-core interrupt deadlock is outside `Ziel`, and `Spec.lean` does not name it
*Files: `grammatik/Grammatik/Korpus59.lean:14,120`; `Zielsatz/Spec.lean:417`;
`Unterbrechung.lean` header.*

- The Einheit models an `entry … dispatch` root as a start thread (Spec.lean:417, "`entry`/`boot`
  dispatch roots").
- `D.maskiert` is read by nothing in `Zielsatz/` or in `Akzeptiert`. It appears only in
  `Unterbrechung.lean`, which is not part of `gabbro_ziel`.
- Consequence: the model of `beispiele/gift/460` has the same `Akzeptiert = true` and the same
  `korpus59_ziel` as the model of `beispiele/59`, because the two differ only in
  `kMaskiert .takt`.
- Failure scenario: a thread holds `TAKT` (unmasked), and the timer handler on the same core
  preempts it and spins on `TAKT`. That is a real deadlock, and Rust `H102` refuses it.
- In the G model the handler is an independent thread, so "no deadlock / `KeinWarteZyklus`"
  holds anyway.
- So H102 is a Rust-only guarantee with no counterpart in the goal. Spec's NOT CLAIMED list
  (lines 370–385) does not name "handlers preempting their own core" as an assumption.
- Lane 203's report calls `masks irqs` "a model bit". That is true, but the bit is inert for
  the goal.
- **Proposal:** name it in Spec's NOT CLAIMED list (or as a runtime assumption: a handler never
  shares a core with a thread holding an unmasked lock it takes), or carry `MaskenOrdnung` into
  `Laufzeit`. That is a `Spec.lean` diff for the orchestrator/Simon, so it was not done here.

### F2 (medium): Korpus125's constant `return 0` is not forced. The "proved necessary" claim is bigger than the proof
*File: `grammatik/Grammatik/Korpus125.lean:173` (`kRumpfLese`). Report
`messung/muse/MUSE-REPORT-203.md` §3: "the reshape is proved necessary, twice".*

- What the two lemmas prove:
  - `offen125_ret_unter_locks` proves only that a `ret` at Λ = `[held WACHE]` is untypeable.
  - `offen125_lese_aussen` proves only that `z` cannot be read with Λ = `[]`.
- A value-faithful term exists anyway. `Stmt.locks`'s body shares `Γ`, and `Stmt.assignVar`
  exists (Syntax.lean:464, 485), so this is a G term:

  ```
  .bind kNull (.cons (.locks w _ (.cons (.assignGlob z (.glob z kGdarfW) rfl kGdarfW)
        (.cons (.assignVar .hier (.glob z kGdarfW)) .nil))) (.ret (.wert (.var .hier)) .nil))
  ```

  It is `let r = 0; locks WACHE { z = z; r = z; } return r;`. It returns the value of `z` read
  under the lock, which is what the source means.
- So `offen125` is a gap of the exporter's form, not of G. The model returns a different value
  than the source.
- **Does the reshape hide a guarantee gap? No:**
  - every contract is `.wahr`;
  - no lock invariant is declared;
  - the writeback read of `z` still happens under `WACHE`.

  No obligation, race or lock-discipline fact depends on the returned value. Also note that the
  model's `z = z` folds away the source's `let v = z; z = v`, which has the same effect.
- **Proposal:** build the faithful body (a small follow-up that needs a build: the
  `kP_koerper_lese` simp proofs must be re-run), then rename `korpus125_*_umgestaltet` to
  `korpus125_*`. Comments are corrected in `407e86c6`; the term was not built.

### F3 (medium-low): the O12 `RELEASE HOLDS (syntactic)` row can acquit a broken release
*Files: `crates/gabbro-check/src/obligations_g.rs:289–307, 381–411, 448–545`, and
`gegenbeispiel.rs:1942–2185`, which holds the same logic (diffed: only the wording differs).*

The code comment claims "the section may oblige, it may not acquit". Three reasons that is false:

1. **Order-blind union.** `hat` is the union of every unconditional callee's promised cells.
   Take `locks L { setze(30); stoere(); }`, where `stoere` has `writes konto.slots` and no
   `ensures`. Result: HOLDS. `stoere` overwrote the promised cells after `setze`.
2. **Direct writes are ignored.** Take `locks L { setze(30); konto.slots[1].stand = 5; }`.
   Result: HOLDS. The catch-all `_ => rufe_bedingt(..)` at line 307 drops the `Zuweisung`
   silently. The same holds for `Publish`/`Exchange`, calls on an assignment's right-hand side,
   and `Observiert` blocks. `sperr_abschnitte` also skips `Observiert` (line ~411 `_ => {}`), so
   a `locks` nested in `observes` gets no row at all.
3. **Name-matched cells.** An invariant `forall i … konto.slots[i].stand …` and a callee
   `ensures konto.slots[i].stand == x`, with a parameter that happens to be named `i`, produce
   the same cell string. Result: HOLDS.

- Impact: an informational comment in `obligations`/`counterexample` output. No verdict, no
  diagnostic, and the row is labelled "not a proof". So nothing is weakened, but a user can be
  told HOLDS for a release that fails.
- **Minimal repair (not done, needs a build and two test files):**
  - any `Zuweisung`/`Publish`/`Exchange`, and any unconditional callee after the last promising
    one that writes an invariant table, goes to `unsicher`;
  - render a quantifier-bound index as `[…]`.
