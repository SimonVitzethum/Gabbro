## Lane 207: does the pointer arm accept anything unsafe?

**No.** The change touches only the **exporter** (`lean_g.rs::tr_traverse`). It is not the
checker. `gabbro lean-g` exports only programs the checker accepts with zero errors
(`crates/gabbro-cli/src/main.rs:474-480`), so the arm cannot make the checker accept anything
new. It resolves a name only through `ctx.lookup` to `VTy::Ptr { table, .. }`. `param_ty`
(`lean_g.rs:1405-1426`) builds that type only for `ptr<normal, _> T` with `T` a declared
table. Device address spaces are refused (`LG002`), and so is any target that is not a table.
Records are `Tab`s with `count 1`, but the checker's `D018` (`domaene.rs:2364`) only allows
`slots of` over a table or an index, so a record pointer never reaches here. Integers, bools,
index binders and unknown names still refuse `LG006`, and two poison probes pin this. The
two-table positive probe pins that the domain is the table the pointer names (`GTab.T`, never
`GTab.U`). Aliasing does not arise: a table is a single instance, so every `ptr T` names the
one `T`. `lookup` takes the innermost binding.

The claim in the report is modest and accurate: 19 and 46 move from `LG006` to `LG005`, and
**zero programs are gained**.

## Lane 208: is the denominator and the agreement honest?

Mostly yes. The script says, in its header, that it measures **one direction only**. Because
`lean-g` refuses to export a file with errors, every compared program has `rust=accept` by
construction. So "agree" means *Lean `Akzeptiert` also accepts this checker-clean export*. The
coverage block and the `pin:` tally are real improvements: they say how few programs reach the
thread components (4 of 18 per the lane's own run). The vacuity pins K1-K4 are **not hidden
weakenings**. No checker rule was removed or relaxed. The four "vacuous" components are still
**decided by Lean on every export** (each is its own `decide` line in the probe). The pins only
explain why no Rust rule exists for them.

- `stufen`: the floor is an exporter-chosen annotation (`resolve_floors`, `lean_g.rs:1883`),
  the minimum rank taken in the reachable set, not a user declaration. That makes `stufenB`
  true by construction. The lock order is still judged by `fuss`, with `N290`-`N294` on the
  Rust side. This is not a weakening.
- `sperrOrte`: `orte`, `braucht` and `gbraucht` are printed from one guard set. This is
  well-formedness of the exporter, and the pin is real (but see F2).
- `antworten`: `Ax := Empty` and `Reg := Empty` are printed unconditionally
  (`lean_g.rs:4778`, `:4783`). K1 is real.
- `abg` / K4: **decorative.** Every `GFn.X` in an export that elaborates is necessarily a
  constructor, so K4 cannot fire without Lean failing first. It is harmless, but it is not a
  pin (F3).

## Open findings, ranked

**F1 (medium, fixed in `0ac32e54`, unmeasured). The differential never judged global
carriers.** `sonde()` (`instrumente/pruefe-akzeptiert-diff.py`, before the fix at
`:309-314`) built `cs` from `GTab` constructors only. `rennB_iff`
(`grammatik/Grammatik/Zielsatz/Akzeptiert.lean:262`) makes `rennB` the race property only
under `hcs : ∀ c, c ∈ cs`. A tables-only list does not meet that premise, and `.inr GGlob.*`
carriers (exported since lane 198) were never checked. *Scenario:* two concurrent starts each
write an unguarded `static mut`. If the Rust `N300`/`N301` ever missed it, the export's own
`gCs` would make Lean's `rennB` false, but the probe asked Lean about tables only, so the
program would report `agree`. The code comes from lane 196 (`846f519d`), not lane 208. But
lane 208's job was the honest coverage denominator, and its line `renn(>=1 table)` repeated
the blind spot. Today no *concurrent* exported corpus program has a `static` (121 has two,
with zero starts), so the fix probably changes no current verdict. **Not measured.**

**F2 (low, fixed in `12b7c007`, unmeasured). K2 used substring membership.** `"GLock.L" in
"…GLock.L2…"` is true. So a table guarded in `orte` by `L`, whose `braucht` lists only `L2`,
passed the forward check. The back check had the same problem with `GTab.T` against
`GTab.T2`. The pin that exists to catch guard-printing drift could miss exactly that drift
when lock or table names share a prefix.

**F3 (low, open). K4 is decorative, and the merge/TODO wording is slightly bigger than the
measure.** K4 can never fire on an export that elaborates (above). Separately, `TODO.md:318`
and the `c8b9c1a4` message say "five of nine components are decided by existing Rust rules
with zero disagreements". But:
- `frag` is decided by the exporter's `LG004`, not by a checker rule;
- "zero disagreements" is measured only in the Rust-accept direction, over 18 comparable
  programs. The refuse direction rests on gift probes, and the script says so itself.

Suggested wording: "five have a Rust counterpart; no disagreement in the Rust-accept
direction over 18 comparable programs". Not edited here, because `TODO.md` is a ledger file.

**F4 (low, pre-existing, not verified). In `tr_traverse` the table name wins over a
same-named binding in scope.** The table lookup runs before `ctx.lookup`
(`lean_g.rs:~3605-3614`). If a parameter may be named like a table, for example
`fn f(T : ptr<normal, rw> U) { traverse i over slots of T … }`, the export traverses table
`T` while the source means `U`, and the counts may differ. This precedence predates lane 207;
the new arm only resolves names that are *not* tables. I did not verify whether the checker
allows a parameter to shadow a table name. If it does, the order should be scope first.

**F5 (low, history only). The 207 merge message describes the task, not the delivery.**
`9586c8c6` says "Widens gabbro lean-g toward the full Einheit … and obligations --g to state
NutzerPflicht gE". The lane's own report says those five items were already complete from
lane 198. The lane delivered only the pointer arm and tests, and did not touch
`obligations_g.rs`. The report is right and the merge message is wrong. It cannot be rewritten.

**F6 (info). The 208 report says the probes left emission untouched ("named list"), but
they did not.** `4586ceab` had to raise `MARKE_EMIT_M` 141 -> 143, because the ratchet walks
`messung/*/`. The merger caught this. The value 143 was **not re-measured** here. Also, the
report's side observation that "`gabbro lean-g` exits 0 with empty stdout on checker-refused
files" does not match `main.rs:474-490`, which exits 1 and prints "has errors -- no export".
The observation probably came from the wrapper; it was not reproduced.

**F7 (info, open doc debt).** The comment printed by `obligations_g.rs:81-82` ("the export
declares no global (`Glob := Empty`)") is stale since lane 198, as lane 207 reported. It is
not fixed here, because it changes generated output bytes, and that needs a build.
