## 254 — width propagation, checked for soundness

- `breite_weiter(lo, hi, w)` keeps a width only when `0 <= lo` and `hi < 2^w`. Otherwise it gives
  `None`, and a `None` width makes `~` and the bit operations refuse (LG003).
- Arithmetic takes the **left** operand's width:
  - A literal's `VTy` carries `bits: None` (`lean_g.rs:2593`), so a literal on the left gives no
    width.
  - `typen::gemeinsame_form` returns `None` for two declared operands of different width or sign.
    So the "left width equals the checker's common form" claim holds wherever a width is printed.
- Signed values: `m1.rs:3084` refuses `~` over a signed word (M137), and `tr_bitop` refuses
  negative ranges. The loss of signedness in `VTy::Int.bits` can therefore not reach an
  unsigned-complement mismatch.
- The annotated `let` pushes the annotation's width with the computed range. The range is still
  checked against the annotation (`check_annotation`), and later assignments are held to the pushed
  range by `tr_value`, so they refuse instead of widening.
- `tr_index` over an integer-typed name goes through `fit` against `Index t`. The proof is `by
  decide` over the printed range, and Lean's kernel re-checks it.

## Findings, by severity

**F1 (high; model fidelity, carried over from G02 and widened by 255).**
`lean_g.rs:1810-1846` now exports `masks irqs` as `D.maskiert`, instead of the earlier LG001
refusal, and `beispiele/59` exports (15 → 16).

- Its `entry zeitgeber vector 32 via idt` travels as an ordinary start (`check_starts`,
  `lean_g.rs:3202`).
- `Akzeptiert`/`Ziel` never read `D.maskiert`: its only uses in `Zielsatz/` are the
  `fun _ => false` fixtures.
- So 59's exported deadlock freedom is a statement about a model in which the interrupt is an
  independent thread. The hazard that `H102` guards (same-core preemption while `TAKT` is held) is
  not in that model.
- The emitter lowers no `cli`/`sti` (`beispiele/59` says so in its own header).
- Nothing false is proved, but a reader of "59 exports under `gabbro_ziel`" could take it for
  interrupt-deadlock freedom. `Spec.lean`'s NOT-CLAIMED list says only "the C and the hardware".

**Recommendation:** add an explicit line to the `Spec.lean` header: *entry/IRQ dispatch roots are
modelled as independent starts; same-core preemption and `masks irqs` (`D.maskiert`) are not read
by `Ziel`; `H102` in Rust is the only guard*. That is a `Spec.lean` diff, so it was not made here.

The "deadline as NO-FORM drop" is not a silent drop:

- the clause was refused before, so no earlier claim is lost;
- the printed header names it wherever a deadline is dropped (`lean_g.rs:4454-4461`);
- the Rust checker still checks it.

**F2 (medium, latent; 253). The checker accepts `start { … }` with only `W003`, and three
guarantees are understated at checker level.** Today only the emitter's `C001`
(`emit.rs:10365`) and the exporter's `LG004` stop the program.

1. **Effects:** `aufrufgraph.rs::sammle_rufe`/`sammle_kanten` walk `eigene_ausdruecke`, which
   excludes `Start` (`lib.rs:900`), and the `match` ends in `_ => {}` (`aufrufgraph.rs:1177`).
   So a starter with `effects { pure }` that starts a root which writes a table gets no `E008`.
   Only `namen.rs::rumpf_falten` (primitive facts) sees the roots.
2. **Costs:** `kosten.rs:1049` gives `start` a cost of 1, but the starter joins before it
   proceeds. A `costs <= N` on the starter therefore excludes the roots' own run time.
3. **Races and duplicates:** there are no membership, nullary or duplicate checks. `start { h, h }`
   on a function outside `concurrent` passes, and no race pass sees the two instances. This is
   G06's `ws.Nodup` question in a new form.

The lane's own handoff (MUSE-REPORT-253 §5.2) lists 1–3. **Not listed there:** a `start` inside a
`locks L { … }` block, joined while `L` is held, deadlocks if a root takes `L`. Nothing checks this.
The TODO row now names all of it.

**F3 (medium, design; 253). The statement's intended semantics contradicts the export semantics.**
The AST doc says `start` names *already-declared `concurrent` roots*, and the syntax test fixture
(`crates/gabbro-syntax/tests/fadenstart.rs`) writes `concurrent { hauptA, hauptB }` together with
`start { hauptA, hauptB }`. But `lean_g::check_starts` and the generated driver start every
`concurrent` member at boot. If the handoff lane implements the rule "roots must be `concurrent`
members", each root runs twice: once from the declaration and once from the statement. That is
exactly the duplicate-start case that the Lean side refuses (`einzeln : ws.Nodup`, `Spec.lean:467`).
The next lane has to decide which declaration owns a start before it builds the membership rule.

**F4 (medium, latent; 256). The index rule accepts reads the Lean model refuses.**
`zeichenfolge.rs:585-599` accepts `s[k]` for any literal `k < max`, and `gift/1125` (`s[7]` on
`string max 8`) checks clean. But a `string max 8` may hold 0 characters, and the Lean `bindex`
returns `none` for `k >= length` (`ZeichenfolgeGebunden.lean:65`). So checker acceptance does not
imply an in-range read. The lane states this honestly in the `saetze.rs` reservation ("the lowering
lane owes the exact-length side"). It is safe today only because every string program ends at
`C001`. The obligation was missing from TODO and is now booked there (`542883cd`).

- **Off-by-one:** none. `k >= max` refuses and `k < max` accepts, as stated.
- **Concatenation:** `m_a + m_b <= target` is a sound over-approximation of Lean's exact-length
  `bconcat` check.
- **Copying into a shorter max:** caught (N455) at `let`, assignment, `return` and call arguments.
  It is **not** caught at struct/table fields, contracts, `const`/`static` initializers or
  `LetSonst`. These are documented cuts, covered by `C001` only.
- **NUL:** the model is a length-carrying list with no terminator. The lowering must choose a
  representation, and a NUL-terminated buffer needs `max + 1` bytes. Nothing decides this yet.
- **Size of `max`:** `max` is parsed as `u128` with no upper bound. The pass uses saturating sums
  and cannot accept wrongly, but a lowering must refuse maxes it cannot allocate.

**F5 (low; 256). The flat name table can hold a stale max.**
`sammle_lets` (`zeichenfolge.rs:239-269`) collects every `let` of a body into one flat map. An
unannotated `let` whose initializer the pass cannot type **does not touch** the entry. So shadowing
a string parameter with `let s = 5;`, or reusing a name in a sibling block, keeps `Kette(max)`:

- `s + 1` then draws a false `N455`;
- if the shadowing value is itself a longer string from an unresolved call, a copy into a
  shorter slot is accepted on the stale max.

This contradicts the sentence "shadowed names drop out". The minimal repair is to mark the name as
unknown (`None`) on an unannotated, untypable `let`. It was **not** applied: it changes verdicts in
both directions and needs a probe pair and a build. `C001` keeps it from reaching C.

**F6 (low; 256). A decorative conjunct in the witness.**
`bounded_string_zeuge` joins the string facts with `refB_erreicht`/`refB_schreibt`, a
reference-machine run that has nothing to do with strings. The string theorems have no
∀-over-syntax premise, so the witness rule does not strictly apply. The conjunct adds nothing, and it
is the lane-147 "decorative witness" shape. No `sorry`, `admit`, `axiom` or `native_decide` was found
in the file, and the file is imported in `grammatik/Grammatik.lean:311`.
