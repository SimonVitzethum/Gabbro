## The merger fixup 46c15a1a — equivalence

Before the fixup, `entferne_innen` (147) and `urteil_innen` (148) used nested `if`s with no
`else` arms, apart from the explicit age branch. After it, each is one `&&` chain whose
conjuncts come in the same order. The emitter lowers `BinOp::Und` to C `&&` (`emit.rs:16066`),
which short-circuits. Every conjunct is a pure slot read at `r : index into T`, so it cannot
fault and has no effect. The nested and flat forms therefore agree on the value, the reads that
happen and the order of those reads. The cost model bills both sides of `&&`
(`kosten.rs:2070`, `pred_kosten(a) + pred_kosten(b)`). That is the same worst case as the
nested reads, so the cost bounds stay sound. The fall-through `return MISS` is unchanged, and
so is the inner `else { if … && … }` structure in 148. The new comment said "same five
reads", but the chain reads six fields (`belegt` + 5). That is fixed.

## Program correctness by reading (147/148)

- **Index arithmetic:** `h % 1024` is followed by `narrow r to 0 ..< 1024`, so the index is in
  range. `runde ∈ 0..15` gives `basis = runde*64 ∈ 0..960` (`RASTER_MAX`). With `k ∈ 0..63`,
  `basis + k ≤ 1023`, and the `narrow` arm can never be taken. No subtraction is used anywhere.
- **Overflow:** `alter += 1` sits behind `alter >= 63`, and `alter` is declared `0..63`.
  `runde + 1` sits behind `>= 15`. `*%` on bare `u32` becomes unsigned C multiplication, which
  wraps without UB. The largest shifted value in 151, `v << s` with `v ≤ 255` and `s ≤ 24`,
  fits in a u32.
- **Lock discipline:** every carrier is inside `protects` (`regeln, befehl, runde, haben` and
  `stroeme, runde`). Every toucher carries `requires Held(..)`, and the public entry points take
  the lock once. The worst holder is `tick`, which the report puts at 8320 ops against
  `held <= 16384`. Unrolling 64 × `fenster_schritt` (≤128) comes to 8192 ops plus the round
  step, which is consistent with that bound.
- **Fail closed:** `freigeben` zeroes all match fields, and no path accepts on a stale tuple. A
  hit refreshes the age to 0, so an entry never expires early.
- **Buffer:** `befehl_nehme` refuses when `n > 512`. The `..` range is inclusive, and
  `haben : 0..512` matches the "512 OK, 513 ZU_LANG" run in the report.

## Findings (ranked)

1. **F1 (medium, quality; comment fixed, code open): the hash is not FNV-1a, and the bucket
   uses only the low 10 bits of each word.**
   - What the code does (`147:111`, `148:90`): it xors and multiplies whole 32-bit words. Real
     FNV-1a works one byte at a time.
   - Why that matters: modulo 2^32, both `^` and `*` carry only upward. So `h % 1024` depends
     only on bits 0..9 of `sip`, `dip`, `sp`, `dp` and `pr`.
   - Measured with a Python model of the exact code:
     - `sip = 10.0.0.5` and `11.0.0.5` land in the same bucket (54).
     - So do `sp = 40000` and `40000 + 1024`.
   - Failure scenario: on a gateway where `dip`, `dp` and `pr` are fixed (one FTP server,
     port 21, TCP), the bucket is a function of `(sip mod 1024, sp mod 1024)`. Clients whose
     addresses differ only above bit 9 fight over the same buckets and get `VOLL`.
   - It stays fail-closed: a collision never produces a wrong ACCEPT, because the full tuple is
     compared.
   - The "3652464371 both ways" in report 236 agrees with a Python model of the same word-wise
     variant, not with the FNV-1a specification.
   - Fix direction (not done, because it is code and unbuilt): fold the result before the
     `%`, as in `h ^ (h >> 16)`, or hash bytes.
   - The comments now state the property.
2. **F2 (low, doc; fixed): the age unit.** `alter` counts sweep visits, and the sweep visits a
   bucket once every 16 ticks. The limit 63 is therefore about 1008 ticks. Report 236 says this
   correctly: an entry lives 1007–1023 ticks. The 148 comment said "the next 63 ticks are paid
   for by this packet", which is off by a factor of 16, and the 147 header left the unit open.
   Both are fixed.
3. **F3 (low, design; open): the 148 data plane is keyed by the CONTROL 5-tuple.**
   `daten_paket(sip, dip, sp, dp, pr, dsip, ddp)` hashes the control tuple, then compares the
   data tuple (`xsip`, `xdp`). A real data-channel packet carries only its own tuple. The caller
   would need the control association in advance, and that association is exactly what an ALG
   table is supposed to provide. The file honestly calls itself a sketch, and 147/148 are
   separate units by design (there is no cross-unit table access). Even so, "answers one
   question per packet" overstates what a packet-driven caller could use.
4. **F4 (low, claim; fixed): the 151/152 cost comparison.** 152 said "~4x the emitted C",
   while both headers book ×3.16. The ×3.16 compares 152's whole guarded read expression
   (79 characters) with 151's slot access alone (25 characters). 151's shift and mask sit
   beside that access and were not counted. The lane's own measured object text runs the
   other way: 151 has 246 bytes of text and 152 has 202. The 152 comment now says that the
   byte side pays with a compare and a trap branch per access, not with code size. The
   headline "x3.16 the C per read" in the 151 header (line 31) is left as the lane booked it.
   Treat it as characters at the access site.
5. **F5 (nit; open): 147's command buffer is only a length gate.** `befehl_schreibe` and
   `befehl_lese` take any `index into befehl`, whatever the value of `haben`. Nothing ties a
   read to the recorded length, so a reader can see stale bytes past `haben`. The report says
   "wiring a real parser … is application work", which is honest. The header line "a longer
   input is REFUSED" is true only of the length.
6. **F6 (nit; open):**
   - 147 has no refresh on the control plane: a live control rule ages out after about 1008
     ticks, whatever the traffic. This is by design, since 148 refreshes, but it is not stated
     in 147.
   - In 147 `tick_runde` (lines 244–312), the body is indented one level too deep. This is
     cosmetic.
   - `FENSTER` and `RUNDEN` are declared and never used. The literal `64` in `runde * 64`
     duplicates `FENSTER`.
