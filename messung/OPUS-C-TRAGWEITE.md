# Opus agent C — how far a green `lake build` reaches (the reach audit)

*2026-09-26, worktree `agent-addcada38733de2a3`, base `a346748f` (master after "Merge Opus A").
Everything measured locally with the binary built from this tree (`cargo build`, debug), the
queued wrappers for every Lean run. `free -g` beside the heavy runs: 31 GB total, 18 GB
available.*

**Simon's sentence (2026-09-26):** *"When Lean is green, Gabbro carries everything except the
things named in the Spec."* This file lists every way it was NOT true on the base, with the
number measured today, and for each gap: whether this lane closes it, and which line of
`Spec.lean`'s header names what stays open. Section 1 is the state BEFORE; section 5 the state
after this lane.

The most frequent single messages: `function X is not impl` 12 (`spec`, `const`, `raw`,

## 3. The mechanism (what "Lean green" now means per program)

* `grammatik/Grammatik/Zertifikat/` holds ONE GENERATED file per exported, accepted program:
  the output of `gabbro obligations --g <program>` byte for byte (the exported `Einheit`, the
  complete member lists, `gCheck : akzeptiert_pruefer.akzeptiert gE gFs gLs gCs = true := by
  decide`, and `gP_gabbro`, the goal theorem on the program with the user's duty as the
  hypothesis). 104 and 108 keep their existing `GenOblig104/108.lean`.
* `grammatik/Grammatik/Zertifikate.lean` imports every certificate; `Grammatik.lean` imports
  it, so `./lean-bau` elaborates every one and decides every checker premise.
* `grammatik/Grammatik/Zertifikat/REGISTER.txt` is THE ONE LIST: every accepted program under
  `beispiele/`, either `CERTIFIED` (module, chain state, hand-term note) or `UNCERTIFIED` (the
  exporter's code and message).
* The cargo test `tests/zertifikate.rs` recomputes all three from the tree and fails when any
  byte differs: a new accepted program without a certificate or a registry row, a stale
  certificate, a registry row for a program that now exports, an umbrella that misses a module.
  `GABBRO_ZERTIFIKATE=schreiben cargo test --test zertifikate` rewrites them.

## 4. Measuring ALL refusals, not the first (why the register does not shrink in bulk)

The exporter stops at its first refusal, so section 1.1 counts one code per program. A
throwaway build that continues past refusals at the item and function level (collected, then
reverted; `.tmp/alle.py`, not committed) lists the refusal SHAPES per program — a lower bound,
since later stages (locks, `sp0`, starts, emission) did not run on a partial model:

| shapes per program | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 9 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| UNCERTIFIED programs | 62 | 57 | 31 | 16 | 4 | 4 | 2 | 1 |

Most frequent shapes (programs): `function X is not impl` 37 (`extern`, `library`, `raw`,
`const`, `spec`), `assume` 24, a pointer naming no table 20, `device` 19, address spaces 19, a
declaration without a table 19, `atomic` 17, non-scalar `static` 15, table invariants/`ops` 14,
`format` 11. Experiment: skipping every `extern fn` (the axiom export G supports) gained **0**
programs — each of the six met another shape next. The two shapes with a single-program yield
that are not exporter rules but MODEL decisions: a tail `let` of a call (110) and `return` under
`locks` (125) need an `Endblock` constructor G does not have (`Endblock` has `bind` of an
expression only), so a faithful export needs a change of `Syntax.lean`, not of `lean_g.rs`.

What WAS cheap and faithful: constants. The exporter refused every `const` with an expression
initializer and every body naming a const, although its own ledger promised "inlined at every
use". It now takes the checker's folder (`Umgebung::konst_wert`, which the emitter's `#define`s
come from) and treats `const fn` as comptime. Gain: `beispiele/93` certified; `beispiele/11`
moved to its next shape (an atomic).
